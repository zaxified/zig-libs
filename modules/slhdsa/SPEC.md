## Design & invariants

**Spec:** NIST FIPS 205, "Stateless Hash-Based Digital Signature Standard"
(August 2024) — the standardized SPHINCS+. Implemented: Algorithms 2/4
(toInt/base_2b), 5-8 (WOTS+), 9-11 (XMSS), 12-13 (hypertree), 14-17
(FORS), 18-20 (internal keygen/sign/verify), 22/24 (pure external
sign/verify with context), 23/25 (HashSLH-DSA pre-hash sign/verify), and **both §11 hash instantiations** over all
twelve Table 2 parameter sets:

- **§11.1 SHAKE:** F/H/T_l/PRF = SHAKE256(PK.seed ‖ ADRS ‖ …, 8n) with the
  full 32-byte ADRS; H_msg = SHAKE256(R ‖ PK.seed ‖ PK.root ‖ M, 8m);
  PRF_msg = SHAKE256(SK.prf ‖ opt_rand ‖ M, 8n).
- **§11.2 SHA2:** compressed 22-byte ADRS; F/PRF =
  Trunc_n(SHA-256(PK.seed ‖ toByte(0, 64−n) ‖ ADRS_c ‖ …)) at **every**
  category; category 1 uses SHA-256 for H/T_l (block-padded to 64),
  MGF1-SHA-256 for H_msg and HMAC-SHA-256 for PRF_msg; categories 3/5 use
  SHA-512 for H/T_l (block-padded to 128), MGF1-SHA-512 and HMAC-SHA-512.

The engine is comptime-generic (`SlhDsa(params.Params)`); the tweakable-hash
context (`Thash`) is comptime-selected by `Params.hash`, so the same
WOTS+/XMSS/hypertree/FORS code serves all twelve sets.

- **KAT-verified against the official NIST oracle, per parameter set.**
  Byte-exact vectors from the NIST ACVP gen-val JSON
  (`SLH-DSA-keyGen-FIPS205` + `SLH-DSA-sigGen-FIPS205`,
  `internalProjection.json`): for **each of the twelve sets** one keyGen
  case (seeds → pk/sk) and one deterministic internal sigGen case
  (sk + message → full signature, then verified); for SHA2-128f
  additionally a hedged internal case (explicit additionalRandomness) and
  a pure external case with a 110-byte context. Pre-hash:
  `preHash` groups of sigGen (every one of the twelve PH
  functions once, plus a hedged case, on SHA2-128f and SHAKE-128f) and sigVer
  (valid signature; modified message, R and SIGFORS). A single wrong bit
  anywhere in the ADRS handling, hash instantiation (incl. the SHA-256 vs
  SHA-512 split and the SHAKE full-ADRS path), WOTS+/XMSS/FORS structure
  or index arithmetic changes the multi-kilobyte signature, so
  byte-exactness across all twelve sets exercises the entire construction
  at every n/h/d/a/k combination. Exact tgId/tcIds in
  `src/kat_vectors.zig`; tests in `src/kat_test.zig`.
- **No new cryptographic primitive.** Everything reduces to std.crypto's
  SHA-256/SHA-512, HMAC over them, and SHAKE256. The only original code is
  FIPS 205's own structure (addresses, chains, trees, index arithmetic).
  The one deviation from the naive spec text is the standard midstate
  optimization: PK.seed ‖ toByte(0, block−n) is exactly one compression
  block for the SHA-2 hashes, absorbed once per keygen/sign/verify and the
  midstate copied per hash call (for SHAKE the sponge state after
  absorbing PK.seed is copied the same way) — an implementation of the
  same function, covered by the KATs.
- **HashSLH-DSA pre-hash (§10.2.2, Algorithms 23/25).**
  `M' = 0x01 ‖ len(ctx) ‖ ctx ‖ OID ‖ PH(M)` goes into the same internal
  sign/verify as the pure `M'` (prefix octet 0x00); `src/prehash.zig` holds the
  `PreHash` enum (the twelve approved PH functions, SHAKE128 → 32 B, SHAKE256 →
  64 B) with the DER-encoded OIDs (2.16.840.1.101.3.4.2.1–12). API, shaped like
  `sign`/`verify` (`out` pointer, `ctx` ≤ 255, `addrnd: ?[n]u8`) with a `PreHash`
  argument: `signPrehash`/`verifyPrehash` take the message and hash it inside (the
  common case, consistent with `sign` taking the message), and
  `signPrehashDigest`/`verifyPrehashDigest` take a caller-computed digest, whose length
  is checked against `ph.digestLength()` (`error.DigestLengthMismatch` on sign,
  `false` on verify) — the HSM / firmware-image flow. The message entry points
  hold it in memory (one slice); a caller hashing a stream uses the digest ones.
  The OID inside `M'` is what makes a pre-hash signature unusable as a pure one or
  under another PH. Verified against NIST ACVP pre-hash sigGen/sigVer groups.
- **Malformed input → `false`/typed error, never a panic.** `verify`
  length-checks the signature (exact `signature_length`) and context
  (≤ 255) before any indexing; everything after is fixed-size. `sign`
  returns `error.ContextTooLong` for a context over 255 bytes. Message
  bytes are only ever streamed into hashes. Verified in Debug AND
  ReleaseFast (`zig build test-slhdsa -Doptimize=ReleaseFast`) so
  illegal-behavior checks ran over the whole KAT battery.
- **Statelessness is the scheme's own property** — no key state to update
  after signing (unlike XMSS/LMS), so the API is plain value types and
  `meta.concurrency = .reentrant` holds trivially.
- **Comptime parameterization.** `params.Params` carries every Table 2
  knob; `Params.validate()` compile-time-checks the internal relations
  (n ∈ {16, 24, 32}, h = h'·d, m = its three digest slices, tree index
  ≤ 64 bits, lg_w = 4).

## Threat model / out of scope

- **Signing is not constant-time hardened.** Verification is public-input;
  for signing, hash-based schemes have no secret-dependent branching in
  the structure itself (chain lengths derive from the public digest), but
  no systematic side-channel review was done. Secret keys are not zeroized
  on drop — callers with a real key-hygiene requirement must
  `std.crypto.secureZero` their copies.
- **Dead stack:** secrets cross the API by pointer (`*const SecretKey`,
  `*const [n]u8` seeds) and results come back through `out` parameters, so the library
  makes no by-value copy of SK.seed / SK.prf; `keyGenFromSeed`, `signInternal` and `sign`
  run their body one frame down and zero the stack it dirtied (`src/burn.zig`).
  `src/stackprobe_test.zig` (ReleaseFast only) scans a 1 MiB window below the call for
  SK.seed, SK.prf, the HMAC key blocks of PRF_msg and the top-layer WOTS+ chain-start
  secrets; 0 residue, negative control 0, positive control found. The caller's own
  copy of the key (the `KeyPair` it passed in) is, as before, its to wipe.
- **Deterministic vs hedged signing:** `addrnd = null` is the FIPS 205
  deterministic variant (opt_rand = PK.seed). FIPS 205 recommends hedged
  signing where randomness is available (fault-attack + multi-target
  resistance); callers supply the n random bytes — this module never
  reaches for OS entropy itself.
- **Randomness is the caller's.** The `keyGen`/`sign` seeds and `addrnd` are caller-supplied by design (std removed
  `std.crypto.random` in 0.16; still absent in 0.17).
- **Signature size is inherent:** 7 856 B (128s) up to 49 856 B (256f) per
  signature — see the size table in README.md. Protocol designs that
  cannot carry that should pick a different scheme; within SLH-DSA the
  "s" sets trade much slower signing for the smallest signatures.

## Verification

Run: `scripts/modtest slhdsa`; fuzz: `SLHDSA_FUZZ=<runs>[,<first seed>]`
(testkit's deterministic driver, harnesses `slhdsa-sha2-128f-verify` and `slhdsa-shake-128f-verify`; never
`zig build --fuzz`); constant time: `scripts/checks/ctgrind.sh slhdsa`.

- **NIST ACVP known-answer tests** (`src/kat_test.zig`, vectors in `src/kat_vectors.zig`): for each of the twelve sets
  one keyGen case and one deterministic internal sigGen case, byte-exact; SHA2-128f also a hedged internal case and a
  pure case with a 110-byte context; pre-hash sigGen on SHA2-128f and SHAKE-128f (every one of the twelve PH
  functions, deterministic and hedged) and sigVer (valid; modified message, R and SIGFORS).
- **Components** (`src/engine.zig`, `src/address.zig`, `src/params.zig`, `src/prehash.zig`): WOTS+, XMSS and FORS
  round-trips (SHA2 category 1, SHAKE, SHA2 category 3), `base_2b` and ADRS bit layouts (including the 12/14-bit FORS
  digits), Table 2 derived lengths for every set, PH OID encodings and digest lengths, key serialization.
- **Round trips and tamper:** keygen, sign, verify (SHA2 and SHAKE, with context); bit flips in R / FORS / hypertree
  regions, wrong message, context, key and lengths, an oversized context; hedged differs from deterministic; the
  digest pre-hash entry points check lengths and `sign(digest)` equals `sign(message)`.
- **No-panic sweep** (`src/sweep_test.zig`): every wrong signature length, a full-length garbage signature, all-ones
  and all-zero keys, a 256-byte context and wrong digest lengths are `false` or a typed error.
- **Fuzz:** both verify harnesses at `.scale` 10 (a run is up to five verifications of a 17 KiB signature), with
  reach checks.
- **Constant time:** `src/ctgrind_harness.zig` (`SK.seed` and `SK.prf` tainted); the verdicts are the card's
  Hardening line.
- **Dead stack:** `src/stackprobe_test.zig`, ReleaseFast only.
- **Oracle:** NIST ACVP gen-val vectors (`SLH-DSA-keyGen-FIPS205`, `SLH-DSA-sigGen-FIPS205`,
  `SLH-DSA-sigVer-FIPS205`, `internalProjection.json` from the ACVP-Server repository), the corpus NIST uses for
  FIPS 205 validation testing; frozen vectors only, no interop program.
- **Audit:** the card's `**Audit:**` line is the current score, cumulative over the last whole-module mutation run
  and the delta runs after it. The whole-module run (227 mutants, one schemata build over
  `engine.zig`, `address.zig` and `prehash.zig`) covered base_2^b, both hash instantiations (the PK.seed prefix, the
  compressed and the full ADRS, F/H/T_l, H_msg with its MGF1 loop, PRF_msg), the WOTS+ chains and checksum, XMSS
  node / sign / pkFromSig, the hypertree layer and index handling, FORS, every ADRS setter and its byte offset, the
  key codecs, the pure and pre-hash message prefixes, the 255-byte context bound and the signature and digest length
  guards of every entry point, and the OID and digest-length tables. 223 killed, 4 equivalent: `j < d - 1` in the
  hypertree (cost-only: the last layer's root is never read), the `setTreeHeight(0)` in `forsNode` (the clear in
  `setTypeAndClear` already zeroed that word), and the `- 1` in `(index - 1) / 2` on the right-child branch of
  `xmssPkFromSig` and `forsPkFromSig` (the index is odd there, so `(odd - 1) / 2 == odd / 2`). Not mutated:
  `params.zig`, the `PreHash` hash switch and `tree_mask` (comptime, which a runtime switch cannot reach; Table 2
  and the ACVP vectors pin them) and the stack burns (visible only to the ReleaseFast probe). One test came out of
  it, in `src/kat_test.zig`: a 255-byte context through `signPrehashDigest` / `verifyPrehashDigest`, and a
  signature over a wrong-length digest built with `signInternal`, which `verifyPrehashDigest` must refuse.

## Performance

`zig build bench-slhdsa` (`tools/bench.zig`, ReleaseFast, `BENCH_ROUNDS=5`) against the SLH-DSA of the system
OpenSSL (`tools/c_bench/foreign_bench.c`, built with `zig cc`), sign / verify / keygen over six sets; the card's

pinned in this tree.

## What is deliberately not done

- **Streaming / incremental signing APIs** — the pre-hash entry points (`signPrehashDigest` /
  `verifyPrehashDigest`) are the answer for digests computed elsewhere.

## Backlog / deferred

- **Stack probe does not recompute FORS leaf secrets.** They sit at a message-dependent address (the tree and leaf come
  out of H_msg), which the probe would have to reimplement. The probe's SK.seed windows and the WOTS+ chain-start
  secrets (same `F(PK.seed, ADRS, SK.seed)` step) cover the inputs and the same code path; a differential needle
  would need H_msg exposed to tests.
