# unitext

Unicode text algorithms on UTF-8 strings, Unicode 17.0.0: **full case mapping**
(`lower`, `upper`, `title`, `capitalize`, `swapcase`, `casefold`; ß → SS, ŉ → ʼN,
İ → i̇, Final_Sigma), **normalization** (`normalize` NFC / NFD / NFKC / NFKD,
`quickCheck`, `isNormalized`), **`unaccent`** (`"ŽLUŤOUČKÝ KŮŇ"` → `"ZLUTOUCKY KUN"`,
`Łódź` → `Lodz`, `Straße` → `Strasse`) and the Python-`str` **classification**
(`isAlpha`, `isDecimal`, `isDigit`, `isNumeric`, `isAlnum`, `isSpace`, `isUpper`,
`isLower`, `isTitle`, `isPrintable`, `isAscii`) with per-code-point properties
(`generalCategory`, `combiningClass`, `toLowerCp` …).

```zig
const ut = @import("unitext");

const s = try ut.upper(gpa, "straße", .{});            // "STRASSE"
defer gpa.free(s);
const n = try ut.normalize(gpa, "e\u{301}", .nfc, .{}); // "é" (one code point)
defer gpa.free(n);
const slug = try ut.unaccent(gpa, "Příliš žluťoučký kůň", .{}); // "Prilis zlutoucky kun"
defer gpa.free(slug);
if (try ut.isAlpha(name, .{ .invalid_utf8 = .replace })) { ... }
try ut.lowerTo(&writer, bytes, .{});                    // no allocation
```

Every string function has an allocating form and a `…To(writer, …)` form. Input is
UTF-8; `Options.invalid_utf8` is `.reject` (the default, `error.InvalidUtf8`),
`.replace` (U+FFFD per maximal subpart) or `.pass_through` (the bad bytes are copied).
`Options.max_output` / `max_segment` bound what a hostile input can make the module
allocate (`error.TooLarge`). The behaviour is CPython's `str` and `unicodedata`
(compared code point by code point), Rust's `to_lowercase` / `to_uppercase` and
`unicode-normalization`, Go's `x/text/unicode/norm`; each function's doc comment says
which and where they differ. Not here: collation, grapheme / word segmentation, bidi,
IDNA, East Asian width, language-tailored case rules — SPEC.md says why.

Status: gap (no zig-libs module had case mapping or normalization; `regex` has only
simple case-fold orbits for `(?i)`, `validate` only the sets of code points that change
under lower/upper). Model-after: CPython `str` + `unicodedata`, Rust std +
`unicode-normalization`, Go `x/text`, ICU. `zig build test-unitext`.

DATA: `src/tables.zig` is generated by `tools/ucd_gen/gen.py` from the Unicode Character
Database 17.0.0 (Unicode License v3; see `NOTICE`); `src/testdata/normalization_test.txt`
is Unicode's `NormalizationTest.txt` with comments removed; `src/testdata/cpython_vectors.txt`
(CPython 3.14.4, `tools/py_oracle.py`) and `src/testdata/rust_vectors.txt` (Rust 1.93,
`tools/rust_case.rs`) are those implementations' answers to this module's own inputs.

Provenance: clean-room — own code from the Unicode Standard (UAX #15, §3.13, SpecialCasing.txt, CaseFolding.txt) and the documented behaviour of CPython, Rust, Go and ICU; no third-party source was ported or studied. The Unicode data in `src/tables.zig` and `src/testdata/normalization_test.txt` carry the Unicode License v3 notice in [`NOTICE`](NOTICE).
