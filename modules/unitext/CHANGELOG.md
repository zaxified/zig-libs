## Unreleased

- **2026-11-09** — **NO CONSUMER-VISIBLE CHANGE:** SPEC Backlog: the `Alphabetic` derived property (`isAlphabeticCp`), asked for by `dataframe`'s polars-style selectors.
- **2026-11-09** — **NEW:** consumer example `example/main.zig` (CONVENTIONS 7.2: 70 `pub fn`): an accent- and case-insensitive search key, `upper` of `ß`, field validation, `lowerTo` into a fixed buffer, the ill-formed-UTF-8 policies; `zig build run-example-unitext`.
- **2026-11-09** — **NEW MODULE:** `unitext` — Unicode 17.0.0 text algorithms on UTF-8: full case mapping (`lower` / `upper` / `title` / `capitalize` / `swapcase` / `casefold`, CPython `str` semantics, Final_Sigma, SpecialCasing; Rust's `to_lowercase` / `to_uppercase` agree on every scalar value), normalization (`normalize` NFC / NFD / NFKC / NFKD, `quickCheck`, `isNormalized`), `unaccent` (NFD, drop nonspacing marks, NFC, plus the letters without decomposition: ł ø đ ħ ŧ ı ŀ …, and `expand_ligatures`: æ œ ß þ ﬁ …), Python `str` classification (`isAlpha` … `isAscii`) and per-code-point properties; ill-formed UTF-8 is a policy (`reject` / `replace` / `pass_through`); allocating and writer forms, `max_output` / `max_segment` caps. Verified against Unicode's `NormalizationTest.txt` (all parts), 12,069 range lines + 2,000 strings of CPython 3.14.4 answers (`tools/py_oracle.py`), and Rust 1.93 `to_lowercase` / `to_uppercase` over every scalar value (`tools/rust_case.rs`); tables generated by `tools/ucd_gen/gen.py`.
