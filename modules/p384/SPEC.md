## What this module is, and what it is not

NIST P-384 (secp384r1): the base field, the scalar field, the group, ECDH and ECDSA-P384 with
RFC 6979 nonces. std ships P-384, but slowly: jwt `ES384` measured 4.2× (sign) and 2.8× (verify)
golang-jwt on std's curve (2026-10-13), and tlsclient's P-384 key share was ~1 ms until it grew a
private comb (2026-10-11). This module is the sibling of `p521` — the same group algorithms, the
same API shape (std's `P384` / `Ecdsa`), so a consumer swaps a type.

**Not here:** wiring into the consumers (jwt `ES384`, tlsclient's key share and CertificateVerify,
x509 P-384 certificates — next, *Open*); hash-to-curve; PKCS#8/SPKI key codecs (the consumers own
their ASN.1); point compression on the ECDH output (x only, as SEC 1 specifies).

## Algorithm

**Curve** — SP 800-186 §3.2.1.4 / FIPS 186-5: p = 2^384 − 2^128 − 2^96 + 2^32 − 1,
y² = x³ − 3x + b, G and n as published (checked by test: G on the curve, n·G = O,
(n − 1)·G = −G; every comb-table entry recomputed by `tools/gen_base_table.py`'s independent
Python affine arithmetic).

**Field** (`field.zig`, `mont.zig`, `fast_core.zig`) — six 64-bit limbs in the Montgomery domain
(a held as a·2^384 mod p), always canonical: std's `P384.Fe` representation, so limbs are
interchangeable (tested). `mont.zig` is the portable arithmetic, shared with the scalar field: a
6 × 6 schoolbook product (the square computes each off-diagonal product once), a six-round
word-by-word reduction (−p⁻¹ mod 2^64 = 2^32 + 1), one masked final subtraction; `add`/`sub` end
in a masked subtract / add of the modulus. On amd64 with ADX and BMI2, `mul` and `sq` run
`fast_core.zig`: CIOS with `MULX` and the two carry chains of `ADCX`/`ADOX` (low halves on CF,
high halves on OF), an eight-register accumulator whose names rotate at comptime instead of a
shift, q = T0·(2^32 + 1) by shift and add, and an XOR-blend final subtraction; the asm text is
generated at comptime from that description. Pinned to the portable product on edge values and
200,000 random pairs (ReleaseFast; 20,000 in Debug). Inversion: a^(p−2) by a fixed chain (runs
x2, x3, x6, x12, x15, x30, x32, x60, x120, x240, x255; then p − 2's tail 0, 32 ones, 64 zeros,
30 ones, 0, 1). Square root: a^((p+1)/4) by the same runs, checked by squaring. Both chains are
tested against square-and-multiply on wide integers.

**Scalars** (`scalar.zig`) — `mont.zig` with n as the modulus. `fromBytesReduce` takes any
48-byte string (< R = 2^384, one multiply by R² mod n); `fromBytes64` adds the high 16 bytes
times 2^384 for 64-byte inputs. Inversion: Fermat with a 4-bit window over the public exponent.

**Group** (`group.zig`) — `p521`'s, with 48-byte scalars. The public type is projective with the
Renes–Costello–Batina complete formulas (a = −3); the scalar loops run in Jacobian coordinates
(dbl-2001-b 3M + 5S, madd-2007-bl 7M + 4S, add-2007-bl 11M + 5S):

- secret scalar (`mul`, ECDH): reduced mod n, s' = min(s, n − s) < 2^383 (the product's y
  negated back by a mask), 77 signed 5-bit digits in [−16, 16], a 16-entry affine table (one
  batch inversion) read by a masked scan; the incomplete formulas' exceptional cases are ruled
  out by the fold except the identity ones, which are blends (proof in `mulCt`'s comment);
- secret scalar times G (key derivation, the ECDSA nonce commitment): the fixed-base comb over
  `base_table.zig` (78 windows × 16 affine points, generated), one mixed addition per window and
  no doubling. A zero digit adds the window's first entry and discards the sum by a mask —
  `addMixedComplete`, without `addMixed`'s identity select (ctgrind found that select lowered to
  a branch on the secret table point, 2026-10-13, the same finding as tlsclient's comb);
- public scalars (`mulPublic`, `mulDoubleBasePublic`; verification): width-5 NAF over the odd
  multiples, and the comb table for G's half; variable time. SEC1 decode accepts `04‖X‖Y`,
  `02/03‖X` and std's `00` identity encoding; coordinates must be < p and on the curve
  (cofactor 1). Key decoders refuse the identity.

**ECDH** — SP 800-56A §5.7.1.2: x of d·Q, 48 bytes big-endian; d in [1, n − 1]
(`NonCanonical` above, `IdentityElement` for 0); Q validated, compressed or uncompressed.

**ECDSA** (`sign.zig`) — FIPS 186-5 §6.4, any hash with a digest ≤ 64 bytes: e = bits2int(H(m))
mod n, a digest longer than 48 bytes truncated to its leftmost 48 (qlen = 384 is whole bytes, so
no shift; Wycheproof SHA-512 rows and RFC 6979 A.2.6 SHA-512 pin it). Nonces: RFC 6979 §3.2 with
HMAC-H, k = T[0..48], retried while k ∉ [1, n − 1]; with `noise`, §3.6's additional data in both
K updates. r = 0 or s = 0 draws the next nonce. `generateDeterministic(seed)`: the same DRBG with
x = 0x01⁴⁸, h = 0⁴⁸ and the seed as additional data (p521's shape; NOT std's key derivation —
known answers in `audit_test.zig`, recomputed by `tools/gen_drbg_kat.py`). DER: short-form
SEQUENCE length only (a P-384 body is ≤ 102 bytes), minimal non-negative INTEGERs of at most 48
magnitude bytes, nothing trailing.

Differences from std's `Ecdsa`, deliberate (as in `p521`): RFC 6979 nonces exactly;
`fromSecretKey` refuses d ≥ n; `PublicKey.fromSec1` refuses the identity; strict DER; `KeyPair`
methods by `*const`; `*Into` twins.

## Constant-time contract

**Secret:** the ECDH secret, the ECDSA secret key and seed, the nonce k, k⁻¹, and every
intermediate of those computations.

**Claimed constant time (machine-checked, `scripts/checks/ctgrind.sh p384`, rows in
`scripts/checks/ctgrind-expected.tsv`):** `P384.mulInto` (`mul`), `KeyPair.fromSecretKeyInto`
(`keygen`), `generateDeterministicInto` + `signPrehashedInto` (`sign`, std's HMAC-SHA-384 counted
as ours), `ecdhInto` (`ecdh`): 0 in-file contexts, ReleaseFast, CPU skylake — which has ADX, so
the asm field is the one measured. The positive control `vartime` (a tainted scalar into
`mulPublic`) reports 11 in-file.

**Declassified, not absent** (`ct.zig`; each a value the API reveals): the range verdict on a
secret scalar; "is the product the identity"; r = 0 / s = 0 and the published r, s; the RFC 6979
retry bit (a candidate ≥ n, probability < 2^−190 per signature).

**Deliberately not constant time:** `mulPublic`, `mulDoubleBasePublic`, `verify` (public inputs);
`Fe.fromBytes`/`fromSec1` (one branch on a public encoding's verdict); `Fe.sqrt` (decompression
of a public point).

**Dead stack** (CONVENTIONS.md §2.1.1): every secret entry point runs under `burn.run`
(`mul_burn` 24 KiB, `sign_burn` 24 KiB, p521's sizes); `stackprobe_test.zig` (testkit) probes
generate/fromSecretKey/sign/ecdh/mul in ReleaseFast: green.

## Limits and refusals

- Scalars and coordinates: exactly 48 bytes; coordinates < p; ECDH/ECDSA secrets in [1, n − 1].
- ECDSA hash: digest ≤ 64 bytes (comptime assert).
- DER signature ≤ 104 bytes (`der_encoded_length_max`); `fromDer` refuses BER, long-form lengths,
  redundant leading zeros, negative integers, trailing bytes.
- P1363 signature: exactly 96 bytes (the type).

## Anchoring

- **External anchor:** NIST CAVP 186-4 ECDSA P-384 — SigVer 75 rows (SHA-1/224/256/384/512, 15
  valid), SigGen 60, KeyPair 10, PKV 12 (4 valid); ECC CDH P-384, 25 rows. Wycheproof secp384r1:
  ECDSA/SHA-384 DER 504 rows (194 valid; every valid signature re-encodes to the same DER) and
  P1363 261, ECDSA/SHA-512 DER 542 (231 valid) and P1363 299, ECDH 798 (771 valid; shared secret
  byte-exact). RFC 6979 A.2.6, all ten rows (SHA-1/224/256/384/512 × "sample"/"test"), with the
  derived k and with the RFC's k given. Every count is asserted (`kat_test.zig`). Recipe with
  pinned sha256 sums: `tools/gen_vectors.py`.
- **External anchor (frozen oracle):** OpenSSL 3.5.5, 24 keys (`tools/openssl_oracle.py` →
  `src/oracle_vectors.zig`): public keys in both SEC1 forms, RFC 6979 signatures byte-identical
  to OpenSSL's `nonce-type:1`, OpenSSL's random-nonce signatures verified (and refused on a
  changed message), ECDH equal to `pkeyutl -derive`.
- **Second implementation:** std's `P384` in the fuzz harness (same public key, same ECDH point,
  std's verifier accepts our signature) and in unit tests (`Fe` limbs, scalar mul/invert).
- **Re-derived:** field and scalar arithmetic against Zig wide integers on edge values and
  thousands of random pairs; asm against the portable product; inversion and square-root chains
  against square-and-multiply; the comb table against `mulPublic`, the Jacobian paths against the
  RCB reference ladder (`mulRcbReference`) on edge scalars.
- **Audit tests** (`audit_test.zig`, from the mutation run): identity inputs to the public
  multiplies and to ECDH, secrets ≥ n, SEC1 trailing bytes, the affine (0, 0), the curve points
  with x = 0 (b is a residue mod p) through `addMixed`, −G and a zero scalar in the double-base
  multiply, a constructed s = 0, DER leading zeros, the two DRBG known answers.
- **Fuzz** (`fuzz_test.zig`, `P384_FUZZ`): genuine signatures verify (raw and DER), flipped bits
  in message / r‖s / public key refused, ECDH symmetric with both peer encodings, constant-time =
  vartime multiply, (a + b)·G = a·G + b·G, determinism, noisy signing, and std as an oracle.

## What is deliberately not done

- **No vendored fiat-crypto** (as `p521`): hand-written Montgomery arithmetic, held by the
  differentials.
- **No ECDH object**: `ecdh`/`ecdhInto` next to `P384.mul`, as std has none for its NIST curves.
- **The comb table is generated** (`tools/gen_base_table.py`), not built at comptime (1248
  points would cost every compile minutes) — the same numbers as tlsclient's
  `p384_base_table.zig`, which this module's table replaces once tlsclient is wired.

## Backlog / deferred

- **Dedicated asm square** — `sq` is `mul(a, a)` on amd64 (~15 of 72 `mulx` to save).
- **Faster scalar inversion** — Fermat costs ~480 Montgomery products per signature; safegcd or
  blinding.
- **ECDH's two field inversions** (table batch + affine output) — ~10 % of an ECDH.
- **Hash-to-curve (RFC 9380 P384_XMD:SHA-384_SSWU_RO_)** — voprf's P384-SHA384 suite.
- **Measure the fastest in the field** (aws-lc) — until then `fastest ?`.
