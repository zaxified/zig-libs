# sha2 — changelog

Newest first. See the root [`CHANGELOG.md`](../../CHANGELOG.md) for which
release tag each entry shipped in, and `CONVENTIONS.md` §8 for the policy.

## Unreleased

- **2026-10-26** — **NO CONSUMER-VISIBLE CHANGE:** audit of the CRYPTOGAMS paths and the run-time dispatch (SPEC § Audit 2026-10-26). The audit found no defect. 25 mutants, all killed, run natively and under `qemu-x86_64 -cpu max` (SHA-NI). New test: `detectCpuPaths` agrees with std's native CPU detection, because a wrong AVX2 or SHA CPUID bit had passed every other test. The audit's source fingerprint now covers `src/asm/*.s`.

- **2026-10-26** — New backends `.cryptogams_shani` (SHA-256/224) and `.cryptogams_avx2` (all): CRYPTOGAMS' SHA-extension and AVX2 block functions (Andy Polyakov's perlasm, the code OpenSSL ships, BSD-style licence: see the new `NOTICE`), embedded as module-level assembly on x86-64 ELF under LLVM and chosen at run time (CPUID SHA + SSSE3, or AVX2 + BMI1 + BMI2 with XGETBV YMM state). A baseline-x86-64 build now takes the fast path. Speed, Kaby Lake (AVX2): 0.40–0.99× OpenSSL 3.5.5 on every row, HMAC 0.52–0.54×, 1.4–1.6× std. The SHA-NI path is verified under `qemu-x86_64 -cpu max` (tests and the 302 000-case OpenSSL oracle); its speed is not measured. Output unchanged. Found on the way: CRYPTOGAMS' SHA-256 AVX2 code ends its loop on a 32-bit pointer compare, so a single call whose remaining input is a multiple of 4 GiB gave a wrong digest. Calls are capped at 2^20 blocks (opt-in regression test `SHA2_BIG=1`). **Consumer-visible:** `Backend` gains two members, so an exhaustive `switch` over it must add them, and `backend()` may return them. New tests: whole-block runs against guard pages, every backend; 40 000 blocks and 2^20 + 3 blocks in one call. Recipe: `tools/gen_cryptogams.sh` (pinned commit and SHA-256s).

- **2026-10-25** — New types `Sha512_224` and `Sha512_256` (FIPS 180-4 §6.7, initial values generated by §5.3.6's procedure and pinned to the standard). New types `Sha256T192`, `Sha512T224` and `Sha512T256`, std's plain truncations with std's names. All are byte-identical to their std namesakes and to OpenSSL. Existing types are unchanged in output. A SHA-224/256 lone block (a short message, `final`'s padding block, HMAC's key pads) now takes a four-word vector schedule: 780 vs 870 cycles for a 32-byte hash in a dependent chain on Kaby Lake. New kept instruments: `tools/interop.zig` (`zig build interop-sha2`), a live oracle against OpenSSL 3 libcrypto over 302 000 cases (digests, `peek`, truncations, HMAC, HKDF), and `tools/bench.zig` (`zig build bench-sha2`), a comparison against OpenSSL EVP. Card: oracle EXTERNAL (E1), Performance measured, ref 0.50–1.15×; bulk from 16 KiB is the cap, see SPEC § Speed. `tools/count.tsv` rewritten: `sha256-1KiB` 31 086, up from 29 732. The scalar padding block measures 31 849 today, so the rise predates this change.

- **2026-10-18** — **NO CONSUMER-VISIBLE CHANGE:** Docs: README/SPEC: 'no per-function target features' and codegen notes labelled as 0.16 measurements, not re-checked on 0.17; std CRC/memset facts updated for 0.17.0.

- **2026-10-17** — Fuzz reach test: a backend label (`simd`, x86-64 AVX2 only) is required only where that backend is compiled (arm64 CI). Test only.

- **2026-10-10** — **NO CONSUMER-VISIBLE CHANGE:** deterministic fuzz driver (`SHA2_FUZZ`): every backend, up to six `update` cuts, `peek` after each cut and the one-shot `hash` agree with std on arbitrary bytes and on lengths at the padding boundaries; HMAC-SHA-256/384/512 (keys short, at and past the block size) and HKDF extract/expand agree with std's. 200,000 runs per harness clean in ReleaseSafe.

- **2026-10-10** — Constant time: new `src/ctgrind_harness.zig` (targets `hash`, `hmac`, ReleaseFast): the message (the secret, when a key or password is hashed) is tainted through `hash`, `update` and `peek` for all four digests at 0..1000 bytes, and through std's `Hmac` over this module's `Sha256`/`Sha512` with the key tainted too. 0 in-file contexts. No code change.

- **2026-10-03** — Audit (review + 54-mutant schemata run): no defect, no surviving

- **2026-09-29** — New module: SHA-224/256/384/512 (FIPS 180-4) as a drop-in for
  `std.crypto.hash.sha2` (same declarations; works under std's `Hmac`/`Hkdf`), with an
  AVX2 multi-block message schedule that makes runs of two or more blocks 1.24–1.40×
  std on x86-64 without SHA-NI, a portable scalar path elsewhere, and std's own
  hardware path for SHA-256 where the target has SHA-NI or ARMv8 `sha2`. Anchored to
  the FIPS 180-4 / NIST example vectors, RFC 4231 (HMAC) and RFC 5869 (HKDF), and
  differentially to std. Requested by qap's performance audit (candidate P3).
