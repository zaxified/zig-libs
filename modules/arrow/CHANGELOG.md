# `arrow` — changelog

Newest first. See the root [`CHANGELOG.md`](../../CHANGELOG.md) for which
release tag each entry shipped in, and `CONVENTIONS.md` §8 for the policy.

## Unreleased

- **2026-11-17** — LZ4_FRAME read: a buffer declaring 0 uncompressed bytes must still hold one LZ4 frame (of nothing), as Arrow C++ hands the bytes to the codec whatever the declared length; junk there is `error.Malformed`. Tests for a frame followed by a skippable or an empty frame.
- **2026-11-17** — Behaviour change: a record batch with a valid (non-null) dictionary index before any `DictionaryBatch` for that id is `error.Malformed`; it used to be read against the first dictionary that came later. Arrow C++ (any record batch before the initial dictionaries is `Invalid`) and arrow-rs (an empty stand-in dictionary, so the index is out of bounds) both refuse it. An all-null batch before the dictionary is still read.
- **2026-11-17** — Behaviour change: LZ4_FRAME body compression is read (no longer `error.Unsupported`) and written (`WriteOptions.compression = .lz4`), as Arrow C++ does it: one LZ4 frame per buffer with liblz4's default preferences (64 KB linked blocks, no content size, no checksums), `compression_level` as liblz4's level (negative = acceleration, 0..2 = default, 3 and up = HC, `error.Unsupported`); on read exactly one LZ4 frame decoding to the declared length, else `error.Malformed`, into the buffer that length sized and within `max_body_bytes`. A buffer that does not shrink is stored raw (-1), as with zstd. The module now depends on `lz4`. Anchored on the `lz4` and `uncompressible_lz4` golden sets (their `.arrow_file`, JSON and `uncompressible_lz4.stream` added); the fuzz corpus carries both lz4 goldens and lz4-written streams.
- **2026-11-17** — Delta mutation of the dictionary replacement / nested dictionary change (33 mutants: 28 killed, 5 equivalent, no finding); tests for the categories of a batch-less read and of an ordered dictionary replaced before any batch. SPEC: the Audit line (cumulative 438/475, 34 equivalent, new `src` hash) and the Hardening line (fuzz re-run, 200 000 seeds, clean, the new goldens and the replacement stream reached). NO CONSUMER-VISIBLE CHANGE.
- **2026-11-17** — Behaviour change: a dictionary REPLACED in a stream (a non-delta `DictionaryBatch` for an id already seen) is read, no longer `error.Unsupported`: each record batch indexes the dictionary current when it was read (as Arrow C++'s and arrow-rs's stream readers do), and a categorical column's categories are the union of the dictionaries its rows use, as pyarrow's `to_pandas` unifies them (first appearance; an unordered column sorted lexically as before, an ordered one in that order). Behaviour change: a replacement in an IPC FILE is now `error.Malformed` (was `Unsupported`; the columnar spec forbids it, Arrow C++ fails it as `Invalid`), and so is a delta for a dictionary not yet sent (was read). A dictionary inside another dictionary's values is read (no longer `Unsupported`): the inner one is decoded first; a dictionary inside its own values, and two fields sharing a dictionary whose values' child dictionaries differ, are `Malformed`. Every replacement is charged to `max_cells` again and all generations together count against `max_rows`. New goldens: `nested_dictionary` (now with its `.arrow_file` and JSON, compared cell by cell) and `4.0.0-shareddict` `shared_dict`; hand-built replacement, delta and nesting tests (`src/dict_test.zig`), a hostile test of 1024 replacements (`max_cells`, `max_rows`) and of 64 zstd replacements (`max_body_bytes`); the fuzz corpus gains both goldens and a replacement stream.
- **2026-11-17** — SPEC: the Audit line records the delta mutation of the Map / run-end metadata change (cumulative 410/442, 29 equivalent; 19 new mutants, all killed, no finding) and the Hardening line the fuzz re-run (200 000 seeds, clean, the Map golden reached). NO CONSUMER-VISIBLE CHANGE.
- **2026-11-17** — Delta mutation of the Map / run-end metadata change: tests for `keysSorted` decoded, encoded and defaulted (`schema.Type.map` round trip), and map entries of a non-struct type with two children or a struct of three fields (`Malformed`). NO CONSUMER-VISIBLE CHANGE.
- **2026-11-17** — Behaviour change: Map is read (no longer `error.Unsupported`), by default, as `list<struct<key, value>>` under the file's own field names, `keysSorted` dropped — what polars (before its map dtype) and pandas see; a write-back is a List of Struct (the "map" tag is lost). As Arrow C++ and arrow-rs require, a Map field without exactly one child, entries that are not a non-nullable struct of two fields, a nullable key field, and a batch whose entries or keys hold a null are `error.Malformed`. `schema.Type` gains `map` (`keysSorted`), decoded and encoded. The `map` and `map_non_canonical` goldens (now with their `.arrow_file` and JSON) are compared cell by cell; hostile tests for map offsets and child lengths under `max_cells`; the fuzz driver adds the map golden.
- **2026-11-17** — Behaviour change: `ReadOptions.metadata` reports a RunEndEncoded field in the shape of the column it reads as — its own pairs, and its `values` field's children as its children (through nested run-end fields); the `run_ends` / `values` fields' own pairs are dropped, as Arrow C++'s IPC reader drops them. A run-end encoded struct's child metadata, written back through `WriteOptions.field_metadata`, now lands on the struct's own fields instead of the first two (the SPEC Open item is closed).
- **2026-11-17** — SPEC Open: REE-of-struct child metadata maps by position on write-back (known, not fixed). NO CONSUMER-VISIBLE CHANGE.
- **2026-11-17** — SPEC: the Audit line records the delta mutation audit of the read-gap wave (cumulative 391/423, 29 equivalent; 98 new mutants, 94 killed, 4 equivalent, no finding) and the Anchoring section gains its paragraph. NO CONSUMER-VISIBLE CHANGE.
- **2026-11-17** — Delta mutation of the read-gap wave: tests for the guards no test pinned (metadata keys charged like values, the footer metadata's own budget, run ends with a dictionary, a views buffer or list-view offsets short of the rows, the u32 cap on list-view elements, the exact `max_cells` of a list view, compressed view batches read whole and projected past broken view buffers). NO CONSUMER-VISIBLE CHANGE.
- **2026-11-17** — Review fix (MED): a ListView whose child reads all-null (a Null child, say) now charges its elements to `max_cells` as a copy would; before, 65 535 rows each naming the whole 65 535-slot child read from ~512 KiB into a frame of ~4.3e9 list elements that a write back then tried to materialise (~16 GiB). Tests: that construction is `LimitExceeded`; projection of a dictionary shared by a picked and an unpicked column, and of a Utf8View dictionary (read, or skipped unread when unused). SPEC Open gains the review's remaining LOWs.
- **2026-11-17** — `WriteOptions.field_metadata`: an entry with more `children` than its field has (a run-end encoded field read, then written back plain without its two children) no longer fails with `error.Unsupported`: the children's metadata is dropped, the field's own kept. More entries than columns stays `error.Unsupported`.
- **2026-11-17** — RunEndEncoded: the last run end may now be greater than the batch length (a sliced array, as the Arrow columnar spec allows); only the batch's rows are expanded, runs past the length fill nothing. A last run end short of the length stays `error.Malformed`.
- **2026-11-17** — SPEC: the Hardening line records the fuzz re-run after the metadata / projection / decimal-width / run-end / view-type wave (200 000 seeds, clean, every new reach label hit). Documentation only; NO CODE CHANGE.
- **2026-11-17** — BinaryView / Utf8View (read as `binary` / `text`) and ListView / LargeListView (read as `list`) are read, no longer `error.Unsupported`. `ipc.RecordBatch` gains `variadic_counts` (`variadicBufferCounts`, read and written); a count per view field and the buffer total are checked (`error.Malformed`). Every view is bounds-checked against its batch's variadic data buffers, its prefix against the data, and every copied byte is charged to `max_cells` before the copy is allocated; Utf8View is UTF-8 checked; a list view's offset and size must lie within its child, its selectors checked against `max_cells` first. `schema.Type` gains `binary_view`, `utf8_view`, `list_view`, `large_list_view`. Never written. New goldens `cpp-21.0.0` binary_view and list_view. The fuzz driver adds the new goldens (reach-labelled per decoder), random one-column projection and metadata reads.
- **2026-11-17** — RunEndEncoded is read (no longer `error.Unsupported`), expanded into a plain column of its values' type: run ends signed Int16/32/64, positive, strictly increasing, ending at the batch length, without nulls (`error.Malformed` otherwise); the expansion is checked against `max_cells` before it is allocated and charged per row and copied byte. `schema.Type` gains `run_end_encoded`. Never written. New golden `cpp-21.0.0` run_end_encoded.
- **2026-11-17** — Decimal32, Decimal64 and Decimal256 are read (as `decimal`), no longer `error.Unsupported`: the first two widen exactly into the Decimal128 rescale path; a Decimal256 is read when it fits an i128 within its declared precision, otherwise refused like any value `dataframe` cannot hold (null under `lossy`). A precision the width cannot hold (Decimal32 > 9, Decimal64 > 18, Decimal256 > 76) is `error.Malformed`. Writing stays Decimal128. New goldens from arrow-testing `cpp-21.0.0` (decimal32, decimal64, decimal256); the `1.0.0` decimal256 refusal fixture is dropped.
- **2026-11-17** — Column projection: `ReadOptions.columns` (new, `[]const ColumnRef`, by name or index) decodes only those top-level columns, in that order (`Metadata.fields` follows); the other columns' buffers are not decompressed, decoded or charged to `max_cells` / `max_body_bytes`, and a dictionary only they use is skipped after its metadata is checked. **Breaking:** `Error` gains `UnknownColumn` (a name no field or two fields have, an index past the last field, a column picked twice). `arrow.KeyValue`, `FieldMetadata`, `Metadata` and `ColumnRef` are re-exported at the top level.
- **2026-11-17** — Key/value metadata both ways: `ReadOptions.metadata` (new, an optional out pointer) receives a `Metadata` — the schema's `custom_metadata`, a `FieldMetadata` tree per column (children included), and a file footer's — copied into the read's arena; `WriteOptions.schema_metadata`, `field_metadata` (by column position; more entries than columns or children is `error.Unsupported`) and `footer_metadata` write them. The schema decode budget now also charges every metadata key and value byte, so one long value behind many entries is `error.Malformed` (`schema.decodeKeyValues` / `encodeKeyValues` are new). The golden test compares every set's metadata with its JSON (`custom_metadata`, `extension`).
- **2026-11-17** — Scope survey against Apache Arrow C++ / pyarrow, arrow-rs, polars, arrow-go, arrow-nanoarrow and the Zig attempts: `**Scope:** core`, `## Compared with` table, gap list under `## Backlog / deferred` (8 proposed, 10 deferred). Documentation only; NO CODE CHANGE.
- **2026-11-17** — SPEC: the Audit line records the independent review and the whole-module mutation audit (297/325, 25 equivalent, 3 unobservable, no finding); the Anchoring section gains its paragraph. NO CONSUMER-VISIBLE CHANGE.
- **2026-11-17** — Mutation audit: tests for the guards no earlier test pinned (hand-built vtables, field offsets, strings without NUL and short vectors; builder alignment and `tbl_len`; the exact `max_depth` and decode-budget boundaries; big-endian schemas, bad type parameters, absent type tables and versions; streams without the end marker; metadata and body padding; null slots, short buffers, negative offsets and indices; shared dictionaries that differ; the date range; `max_rows` / `max_cells` sums; leading mark, footer length and block kinds) in `src/guards_test.zig` and beside each layer. NO CONSUMER-VISIBLE CHANGE.
- **2026-11-17** — Module lands in the collection: catalog, Libraries and Portability tables regenerated; its NEW-MODULES entry is replaced by an `lz4` idea (LZ4_FRAME bodies read as `error.Unsupported` until then). NO CONSUMER-VISIBLE CHANGE beyond that.
- **2026-11-17** — `lossy`: a Date64 off a day boundary is now floored to the calendar day that contains the instant (-1 ms reads as 1969-12-31), not truncated toward zero; nanosecond times still truncate toward zero.
- **2026-11-17** — Review fixes (1 HIGH, 4 MED, 8 LOW). **Breaking:** `Error` gains `InvalidUtf8`;
  `File.batchRows` returns `Error!usize`; with `lossy = false` a nanosecond value with digits past the microsecond
  and a Date64 off a day boundary are `error.Unsupported` (under `lossy` truncated toward zero, no longer floored).
  The schema decoder charges every field, metadata entry and name byte against a budget from the metadata's
  length, so tables shared through FlatBuffers offsets (2.5 KB naming 2^64 fields) are `Malformed` instead of
  an unbounded allocation; `ReadOptions.max_body_bytes` caps the whole read, not each message;
  `ReadOptions.max_cells` (new, 2^28) bounds the array slots a read decodes, dictionary copies included;
  `ReadOptions.validate_utf8` (new, on) checks Utf8 values, and the writer refuses a `.text` cell that is not
  UTF-8; the metadata version must be V4 or V5; Decimal128 is written with the column's real precision and a
  value wider than its declared precision (or than 38 digits) is read like an inexact scale; two fields may share
  a dictionary id when their value types agree; file footer blocks must match their message's lengths and may
  not overlap. New `src/hostile_test.zig` builds each hostile shape with `fb.Builder` and reads it under a
  byte-capped allocator. The example prints the batch as a table and writes under `.zig-cache/tmp/`.
- **2026-11-17** — Wave A5 and A6 part 1: ZSTD body compression read and write (`WriteOptions.compression = .zstd`,
  `compression_level`; a buffer that does not shrink is stored raw; `ReadOptions.max_body_bytes` caps what a
  compressed body may expand to; LZ4_FRAME stays `error.Unsupported`); `ReadOptions.lossy` reads a value
  `dataframe` cannot hold (Decimal128 out of range, a time of 24:00:00, a date outside 0000-9999, an overflowing
  s/ms timestamp) as null and an unknown time zone as a naive column — the default is still `error.Unsupported`;
  the apache/arrow-testing integration golden files (Apache-2.0 data, `NOTICE`) committed and compared field by
  field with their JSON; a deterministic fuzz driver for the readers (`ARROW_FUZZ`); `example/main.zig`. Depends
  on `zstd` too.
- **2026-11-16** — Wave A4: the Arrow IPC file format — `arrow.writeFile`, `arrow.readFile`, and `arrow.openFile`
  with `File.readBatch(i)` for random access to one record batch (footer with dictionary and record batch blocks);
  a Time32/Time64 value outside the day now reads as `error.Unsupported` (a value `dataframe` cannot hold) rather
  than `Malformed`.
- **2026-11-16** — Waves A2 + A3: `arrow.writeStream` / `arrow.readStream` turn a whole `dataframe.Frame` into an
  Arrow IPC stream and back — every column type (widths, decimal, text/binary with Large offsets, date, timestamp
  with zone, duration, time, categorical as a dictionary, list, fixed-size array, struct), nulls, rows per batch,
  dictionary deltas; the reader also takes other units, decimal scales, Float16, any dictionary index type and
  offsets not starting at 0, and refuses every malformed stream with an error. Depends on `dataframe`.
- **2026-11-16** — Wave A3 part 1: IPC framing (`arrow.ipc`): encapsulated messages (continuation marker, legacy framing
  read, 8-byte padding), end of stream, `RecordBatch` / `DictionaryBatch` metadata both ways with every node and buffer
  checked against the body, a body builder with 64-byte buffer alignment.
- **2026-11-16** — Wave A1 part 2: Arrow schema metadata (`arrow.schema`): `Schema` / `Field` / type / `DictionaryEncoding` /
  `KeyValue` tables of `Schema.fbs` and the `Message` envelope, decoded and encoded (Null, Int 8-64, Float 16/32/64, Binary,
  Utf8, Bool, Decimal 32-256, Date, Time, Timestamp with zone, List, Struct, FixedSizeBinary, FixedSizeList, Duration, the
  Large variants; other types are reported as `unsupported` with their id); nesting capped at 64, big-endian refused.
- **2026-11-16** — New module (work in progress, wave A1): the FlatBuffers layer Arrow's metadata is written in — a
  bounds-checked reader (every offset, vtable, vector and string checked; a hostile buffer is `error.Malformed`) and a
  back-to-front builder.
