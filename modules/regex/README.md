# regex

RE2-syntax regular expressions in linear time, at parity with Go's `regexp`: its Perl and POSIX
grammars (Unicode classes `\p{…}` included), leftmost-first and leftmost-longest matching, and its
API — find, submatches, find-all, replace with `$1`/`${name}` templates, split, quote, literal
prefix, matching from a `std.Io.Reader`. Opt-in, the grammar of Rust's `regex` 1.13 (Unicode
`\w \d \s \b`, `(?x)`, `(?R)`, class set operations, every Unicode property), its bytes mode
(haystacks that are not UTF-8), `RegexSet` and `shortestMatch`. A Pike VM over a Thompson NFA, a bit-state backtracker
for short matches, a lazy DFA for yes/no; each visits a (position, instruction) at most once
per step, so no pattern and no
input can make a match explode: safe for patterns and text an attacker controls. Compiling at
comptime needs no allocator, and `isMatch`/`fullMatch` need none either.

- **Model after:** Go `regexp` (RE2 syntax and semantics); anchored on it as a differential oracle,
  and on Rust's `regex` 1.13.1 for `Options.syntax = .rust` the same way.
- **Platform:** any. **Role:** util. **Concurrency:** reentrant — a compiled `Regex` is
  immutable and shared freely; a `Matcher` (submatch scratch) is one per thread.
- **Deps:** none.

Provenance: original work of the zig-libs authors (MIT), clean-room from the syntax as Go's
`regexp/syntax` package documentation and RE2's `doc/syntax.txt` describe it, and Russ Cox's
published descriptions of Thompson NFA / Pike VM matching; no source of Go, RE2 or any other
engine consulted or copied. DATA: `src/go_vectors.zig` holds Go 1.26 `regexp`'s answers to
patterns and inputs generated by our own tooling (`tools/go_regexp_oracle`, crafted + seeded) —
Go is run as a black-box oracle; observed behaviour, no third-party test data reproduced.
`src/rust_vectors.zig` holds Rust `regex` 1.13.1's answers the same way (`tools/rust_regex_oracle`).
`src/casefold.zig` is Unicode 17.0's simple case folding (CaseFolding.txt C + S) and
`src/unicode_tables.zig` Unicode 17.0's properties (categories, scripts, script extensions,
binary properties, age, break properties), both generated by `tools/ucd_unicode` from the UCD
files by the rules of Rust's `regex-syntax` 0.8.11 (checked against that crate, run as a black
box, on Unicode 16.0) and re-encoded (runs, varint ranges) — Unicode License v3, see `NOTICE`.

## Usage

```zig
const regex = @import("regex");

// At compile time: a bad pattern is a compile error.
const id = comptime regex.comptimeCompile("[0-9]+");
if (id.fullMatch(segment)) { ... }        // no allocator

// At run time.
var re = try regex.Regex.compile(gpa, "(?P<y>\\d{4})-(?P<m>\\d{2})");
defer re.deinit(gpa);
if (re.isMatch(text)) { ... }             // no allocator

var m = try regex.Matcher.init(gpa, &re); // scratch sized by the program, once
defer m.deinit();
var groups: [3]?regex.Span = undefined;
if (m.captures(text, 0, &groups)) {
    const year = groups[re.groupIndex("y").?].?.slice(text);
}
var it = m.iterator(text);                // Go's FindAll
while (it.next()) |span| { ... }

// Go's ReplaceAllString, Split, QuoteMeta.
const iso = try re.replaceAll(gpa, "due 2026-10", "${m}/$y");   // "due 10/2026"
defer gpa.free(iso);
var words = m.split(text, null);          // or re.split(gpa, text, limit)
while (words.next()) |piece| { ... }

// POSIX ERE, leftmost-longest (Go's CompilePOSIX); Go's Longest() is `re.longest = true`.
var px = try regex.Regex.compilePosix(gpa, "^[[:alpha:]]+(-[[:alpha:]]+)*");
defer px.deinit(gpa);

// From a reader, in constant memory (Go's MatchReader / FindReaderIndex).
const hit = try re.isMatchReader(&file_reader.interface);

// Rust's grammar; its bytes mode (`regex::bytes`); many patterns in one pass.
var ru = try regex.Regex.compileOptions(gpa, "(?x) \\b{start} \\w+ (?<n>\\d+)", .{ .syntax = .rust });
var raw = try regex.Regex.compileOptions(gpa, "(?-u:\\xff)[a-z]+", .{ .syntax = .rust, .utf8 = false });
var set = try regex.RegexSet.compile(gpa, &.{ "foo\\d+", "bar" }, .{});
var which: [2]bool = undefined;
_ = set.matches(text, &which);
```

## Syntax

Go's `regexp/syntax` (`Perl` flags): literals and `.`; classes `[abc]`, `[^a-z]`, `[[:alpha:]]`
and `[[:^alpha:]]`, `\d \D \s \S \w \W` (ASCII, as RE2); groups `(…)`, `(?:…)`, `(?P<name>…)`,
`(?<name>…)`; `|`; Unicode classes `\pL`, `\p{Greek}`, `\PL`, `\p{^Lu}` — every general
category, its long alias (`\p{Letter}`) and script of Unicode 17.0, plus `Any`, `ASCII`,
`Assigned`, names matched loosely (`\p{lowercase letter}` = `\p{Ll}`), as Go 1.25+; `* + ? {n} {n,} {n,m}` (n, m ≤ 1000) and their lazy `?` forms; flags
`(?i) (?m) (?s) (?U)`, `(?i-s)`, scoped `(?i:…)`; `^ $ \A \z \b \B`; escapes `\a \f \t \n \r \v`,
octal `\123`, `\x7F`, `\x{10FFFF}`, `\Q…\E`, and any punctuation. Without `(?m)`, `$` is the end
of the text (not "before a final newline"). Input is UTF-8, matched per code point; an invalid
byte reads as U+FFFD, one byte wide.

Not here, by design (RE2 leaves them out to keep linear time): backreferences, lookaround,
atomic groups, possessive quantifiers, recursion. `(?i)` matches a code point's whole simple
case-folding orbit, as Go: `(?i)é` matches `É`, `(?i)k` the Kelvin sign, `(?i)θ` all of `θ ϑ Θ ϴ`
(Unicode 17.0; Go 1.26's tables are 15.0, so a code point assigned since is the oracle's listed
UNICODE_VERSION divergence); full folding (`ß` ↔ `ss`) is not RE2's and not here. `\d \s \w`
and `\b` stay ASCII, as RE2. Go 1.26 refuses the 46 script names with an underscore or inner
capital (`\p{Old_Persian}`, `\p{SignWriting}`) against its own documentation; here they work.

**POSIX ERE** (`compilePosix`, Go's `CompilePOSIX`): no Perl escapes, `\p`, `\Q`, `\b \A \z` or
`(?…)`; `^`/`$` match at line breaks; a negated class never matches `\n`; a repetition may repeat
a repetition (`a*?` is `(a*)?`); leftmost-longest.

**Rust** (`Options{ .syntax = .rust }`, Rust's `regex` 1.13 on a `&str`): flags `i m s R U u x`
with `u` on (Unicode `\d \s \w \b`; `(?-u)` for ASCII), `(?x)` whitespace and `#` comments,
CRLF lines `(?mR)`, `\< \> \b{start} \b{end} \b{start-half} \b{end-half}`, `\u`/`\U` escapes,
nested classes and set operations `[a-z&&[^aeiou]]`, `--`, `~~`, every property the crate knows
(`\p{scx=Greek}`, `\p{Alphabetic}`, `\p{Emoji}`, `\p{Age=6.0}`, the break properties), counts up
to 100,000, Unicode group names. Its `\<`, `\b{…}` and `&&` read differently in Go, hence a
grammar of its own (`.perl` stays Go's). **Bytes mode** (`.utf8 = false`, Rust's
`regex::bytes`): `(?-u:\xNN)`, `(?-u).` and `(?-u)` classes match raw bytes; a Unicode class never
matches an invalid byte; an empty match may fall inside a code point; slices only (no `Reader`).

## Limits

**Whatever compiles can be used through every entry point without a panic, and in bounded
memory** — a limit is an error at compile time, safe for patterns an attacker writes. A pattern
within `max_insts` (1024) instructions, 4096 class ranges and 2048 AST nodes compiles in stack or
full-`Builder` scratch; up to `4 * max_insts` (4096; bytes mode `max_insts`) it compiles on the
heap (~2 MiB of scratch, freed), the DFAs and the prefilter stepping aside. Matching never needs
more: `isMatch`/`fullMatch`/`shortestMatch` take ~6 KiB of stack, ~33 KiB for the largest
programs; a `Matcher` at most ~8 MiB (4096 instructions × 64 groups). Past that,
`error.PatternTooLarge` (Go and Rust compile larger programs: the oracles' CAPACITY rows). Always:
at most 63 groups; nesting at most `max_depth` (250); a counted
repetition at most `{1000}` (Rust grammar `{100000}`) and nested counts multiply to at most 1000
(Go's rule). Past one: `error.NestingDepth` / `error.InvalidRepeatSize` / `error.PatternTooLarge`
at compile time — never a truncated program, never a compile that runs away. A `RegexSet` joins up
to `4 * max_insts` instructions and 65,535 class ranges; `matches` fills as many slots as it is
given. The reader functions work with any buffer size; on a bytes-mode `Regex` they return
`error.BytesMode`. Compiling the deepest accepted pattern
fits a 512 KiB thread stack in Debug. A `Matcher` keeps a
pointer to its `Regex`: do not move the `Regex` while a `Matcher` uses it.

## Performance

`Regex.compile` builds a pattern that fits its small builder (256 instructions, ranges and AST
nodes) in ~9 KiB of stack scratch, and only a larger one in a full `Builder` from the allocator.
At compile time the program is analysed once: a pattern anchored at `\A`/`^` is tried at the
start only; a literal prefix of two bytes or more is searched for by a 32-byte vector scan, a
set of up to 32 literal prefixes (`ABCD|CDEF|…`, `(?i)abc`, `foo\d|bar\d`) by Teddy's SIMD
nibble tables, a single first byte by `indexOfScalar`. `isMatch`/`fullMatch` run a lazy DFA on the stack
(programs up to 128 instructions; transitions on ASCII bytes cached). Searches with groups run on
a bit-state backtracker over a window of 256 Kbit / instructions positions — a short match in a
long text included — with one set of captures instead of one per thread; an exploration longer
than the window goes to the Pike VM.

Against Go 1.26 `regexp` (2026-10-07 night, x86-64, ReleaseFast vs `go build`, 18 shared
workloads incl. Go's own Easy/Medium/Hard, same match counts; ours/Go time, lower is better —
ahead on all 18):

| workload | ours/Go |
|---|--:|
| no-match scan of 1 MiB: literal, `[XYZ]ABC…`, `[ -~]*ABC…$`, 12-way alternation, `(?i)…` | 0.02–0.44 |
| find-all over 85 KiB of invoice rows (`INV-…`, with and without groups) | 0.25–0.27 |
| find-all over 1 MiB: dense `[A-Z]+`, literal | 0.24–0.26 |
| find-all over 1 MiB of Czech/Greek/Cyrillic (`\p{L}+`, `\b\w+\b`, `(?i)žluť\w*`, digits) | 0.05–0.32 |
| short-string find / submatches (anchored, pair, email) | 0.58–0.88 |
| compile + submatch per call | 0.39 |

Against quangdn42/regex.zig on bxp's workload: ~3.7× faster per row with the pattern compiled per
call, ~11× on precompiled find-all (SPEC "Compared with").

## Verification

- Go `regexp` as a differential oracle (`tools/go_regexp_oracle`, replayed by
  `src/go_oracle_test.zig`): ~1,800 patterns (crafted syntax edges, every Unicode class name,
  600 random Perl and 300 random POSIX patterns), ~31,000 inputs — compile verdict, group names,
  match, full match, submatch indices, all matches, the same after `Longest()`, through a slice
  and a one-byte-per-read reader; ReplaceAll / Literal / Func, Split, FindAllSubmatch and
  LiteralPrefix on 460 patterns; QuoteMeta of every ASCII byte. Listed divergences, pinned:
  GO_DEFECT, LITERAL_PREFIX, CAPACITY, UNICODE_VERSION (SPEC "Anchoring").
- Rust `regex` 1.13.1 the same way (`tools/rust_regex_oracle`, `src/rust_oracle_test.zig`): 2,374
  patterns and 619 bytes-mode ones, 89 sets, ~62,000 cases — all equal but the pinned SIZE_LIMIT,
  CAPACITY and SHORTEST rows.
- The Unicode tables are generated from the UCD 17.0 by `tools/ucd_unicode`, whose rules give Rust's
  `regex-syntax` tables byte for byte when run on UCD 16.0 (the crate's version; interop lane).
- A deterministic robustness driver and a fuzz harness (`REGEX_FUZZ`, 240,000 runs clean; Go,
  POSIX, Rust and bytes grammars) hold the engines to each other: the DFA and the NFA, the
  backtracker and the Pike VM give the same groups at every start, the reader the slice's
  answer; every pattern its twin written in the other grammar; bytes mode `&str`'s answer;
  a `RegexSet` each pattern's `isMatch`; leftmost-longest and `shortestMatch` independent
  substring references; the prefilter only skips; `replaceAll("$0")` is the identity.
- Four rounds of independent review and mutation testing (SPEC "Verification").
- The exponential-backtracking classic `(a+)+$` on `a…ab` (5,000 bytes) is instant.
