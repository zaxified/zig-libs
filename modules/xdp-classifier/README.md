# xdp-classifier

Pure-Zig **XDP packet classifier** for a LibreQoS-style edge shaper: given a
set of rules `{ ip_prefix (IPv4) -> class_handle:u32 }`, produces a valid,
verifier-passing XDP eBPF program that, per packet, parses Ethernet+IPv4,
performs a longest-prefix-match lookup against a `BPF_MAP_TYPE_LPM_TRIE` map
keyed on the packet's source (or destination) IPv4 address, and stashes the
resolved class handle into a scratch map before returning `XDP_PASS`.

- **Model after:** LibreQoS's classify-then-shape architecture (an XDP
  classification stage feeding a downstream `tc`/CAKE queueing stage) — API
  shape/design reference only, no source ported.
- **Platform:** linux (generated bytecode + map creation are raw
  `std.os.linux.BPF`, same conscious ceiling as `ebpf`). **Role:** util.
  **Concurrency:** single_owner (one instruction buffer per builder call,
  same discipline `ebpf.programs.zig` uses).
- **Deps:** `ebpf` — this module builds a NEW program by composing `ebpf`'s
  already-verifier-proven primitives (see "Tier verdict" below), it does not
  reimplement them.

## Tier verdict: no Fable core

**Fully implemented, nothing gated.** Every function in this module is real
code; every test runs and passes (or skips only for the CAP_BPF/root-gated
real-load checks). See `SPEC.md` for the full argument; the short version:

Every verifier-hard PATTERN this program needs — `ctx->data`/`ctx->data_end`
retyping, bounds-check dominance over a packet region, the map-lookup
pseudo-fd/initialized-key/null-check-before-deref discipline — is already
implemented, golden-tested, and CAP_BPF-load-verified in the sibling `ebpf`
module's `programs.zig` (`xdpFilter`/`kprobeCounter`). `buildClassifierProgram`
does not invent a new pattern; it sequences the SAME ones at different packet
offsets (Ethernet+IPv4 instead of one fixed field), with an LPM-shaped key
instead of an exact-match one, and with a second map-lookup/write-back
appended. The genuinely new part — the bounds-check-then-parse instruction
shape for Ethernet+IPv4 — was additionally cross-checked against real
`clang -O2 -target bpf` disassembly of the equivalent C, not just reasoned
about by analogy (see `src/classifier.zig`'s golden-test provenance comment).

## Scope (v1)

- **IPv4 only.** IPv6 is a documented, additive extension (a second
  bounds-check-and-parse block following the same pattern), not built here.
- **Fixed 20-byte IPv4 header (no options).** The generated program checks
  the IHL nibble equals 5 and falls to the configured default class
  otherwise, rather than computing a variable-length header offset.
  Variable-IHL support is a documented, additive extension.
- **Always classifies, never filters.** The program returns `XDP_PASS` on
  every packet (matched or not) — it writes a class handle for a downstream
  `tc`/queueing stage to act on, it does not drop traffic itself. A
  DROP-on-no-match variant is a one-instruction change but not what this
  fixed contract commits to.
- A too-short packet, a non-IPv4 EtherType, IPv4-with-options, and an LPM
  miss are all deliberately indistinguishable at the output (all four write
  the same configured default class) — see `src/classifier.zig`'s "Design
  note on the shared DEFAULT class".

## API

```zig
const xdp_classifier = @import("xdp-classifier");
const ebpf = @import("ebpf");
const std = @import("std");

// 1. Create the two kernel maps this program needs.
const lpm_fd = try xdp_classifier.createLpmTrieMap(1024); // BPF_MAP_TYPE_LPM_TRIE
const scratch_fd = try xdp_classifier.createScratchMap(); // single-slot BPF_MAP_TYPE_PERCPU_ARRAY

// 2. Validate + load a ruleset into the LPM map.
const rules = [_]xdp_classifier.ClassifierRule{
    .{ .prefix = .{ .addr = .{ 10, 0, 0, 0 }, .prefix_len = 8 }, .class = 1 },
    .{ .prefix = .{ .addr = .{ 10, 1, 0, 0 }, .prefix_len = 16 }, .class = 2 },
};
const rule_set: xdp_classifier.RuleSet = .{ .rules = &rules };
try rule_set.validate(1024);
try xdp_classifier.populateRuleSet(lpm_fd, rule_set);

// 3. Build the program (real, working — no Fable stub).
const insns = xdp_classifier.buildClassifierProgram(.{
    .lpm_map_fd = lpm_fd,
    .scratch_map_fd = scratch_fd,
    .key_field = .src,
    .default_class = 0,
});

// 4. Load + attach it — both real, working code in the sibling `ebpf`
//    module; this module produces `ebpf`-Program-compatible instructions,
//    it does not re-wrap load/attach itself.
const prog: ebpf.Program = .{ .prog_type = .xdp, .insns = insns };
const prog_fd = try ebpf.load(prog, "MIT");
defer std.os.linux.close(prog_fd);
var xdp = try ebpf.attachXdp(gpa, ifindex, prog_fd, .{ .drv_mode = true });
defer xdp.detach() catch {};

// 5. Read back a classification (e.g. from a control-plane poller).
const class = try xdp_classifier.readScratchClass(scratch_fd);
```

Low-level, for callers building their own rule-population/tooling: `Ipv4Prefix`
+ `ClassifierRule` + `RuleSet` (validation), `LpmKey` (the exact 8-byte
`BPF_MAP_TYPE_LPM_TRIE` key encoding, shared byte-for-byte between rule
population and the generated program's runtime key construction), and
`lookupReference` (a pure-Zig longest-prefix-match reference — NOT what the
eBPF program executes, a userspace helper for reasoning about/testing a
ruleset's intended behavior without a kernel).

## Design notes

- **The generated program is ruleset-agnostic.** Rule content (which
  prefixes map to which classes) is runtime data loaded into the
  `BPF_MAP_TYPE_LPM_TRIE` map via `populateRule`/`populateRuleSet` — it is
  never baked into the bytecode. One compiled program works for any
  ruleset; changing rules is a map update, not a program rebuild/reload.
- **`createLpmTrieMap` exists because `std.os.linux.BPF.map_create` has a
  real gap**: `BPF_MAP_TYPE_LPM_TRIE` mandates the `BPF_F_NO_PREALLOC` map
  flag at creation time, and std's wrapper never sets `map_flags`. This
  function fills `Attr`/`MapCreateAttr` directly (every field involved is
  already public in `std`) — see `src/maps.zig`'s doc comment. This stayed
  local to `xdp-classifier` rather than being added to `ebpf` itself: it is
  a single-purpose, single-caller convenience for one map type, not a
  general primitive.
- **The scratch map is `PERCPU_ARRAY`, not a plain `ARRAY`**, so packets
  classified concurrently on different RX queues/CPUs never race on one
  shared slot — the same map-type tradeoff `ebpf.kprobeCounter`'s doc
  comment discusses for its own counter map.
- **Out of scope (deliberate):** IPv6, variable-length IPv4 options, a
  flow-keyed (rather than single-slot) output map, `bpf_xdp_adjust_meta`-based
  per-packet metadata handoff to a downstream `tc` classifier — see
  `SPEC.md`'s backlog for the reasoning behind each.
