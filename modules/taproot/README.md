# taproot

BIP341 Taproot output construction: the key-path tweak that turns an
internal BIP340 key into the key a Taproot output pays to, and script-tree
building (Merkle root, per-leaf control blocks) for script-path spends. Depends on the sibling [`bip340`](../bip340/) module for
`XOnlyPublicKey`/`SecretKey` and the tagged-hash machinery, on `k256` for the secp256k1 point/scalar arithmetic, and on `bitcointx` for the CompactSize encoding of the leaf hash.

The `"TapTweak"` tagged hash, the `TweakedPublicKey` codec, both tweaks (`tweakPublicKey`/`tweakSecretKey`) and the
script-tree builder are checked byte-exact against the official BIP341 `wallet-test-vectors.json`. See `SPEC.md` for the
design, threat model and verification.

| File | Contents |
|---|---|
| `root.zig` | `tapTweakHash` (BIP341's `"TapTweak"` tagged hash), `TweakedPublicKey` (x-only output key + parity, codec), `TweakError`/`TweakResult`, and the crypto cores `tweakPublicKey`/`tweakSecretKey` |
| `tree.zig` | script trees: `tapLeafHash`, `tapBranchHash`, `Node`/`DepthLeaf`, `buildFromTree`/`buildFromLeaves`/`buildFromWeights` (Huffman layout from `WeightedLeaf`s, as rust-bitcoin `with_huffman_tree`) → `SpendInfo` (Merkle root, output key, per-leaf path + `controlBlock`) |
| `tree_vectors.zig` / `tree_test.zig` | the 6 script-tree rows (12 control blocks) of the BIP341 vectors, generated by `tools/gen_tree_vectors.py`, and their byte-exact tests |
| `kat_vectors.zig` | 7 rows from the official BIP341 wallet test vectors (public-key tweak + secret-key tweak paired by `internalPubkey`) |
| `fuzz_test.zig` / `stackprobe_test.zig` / `ctgrind_harness.zig` | the `TAPROOT_FUZZ` driver harnesses, the dead-stack probe of `tweakSecretKey`, the constant-time (valgrind) harness |
| `kat_test.zig` | KAT assertions against all 7 rows: `tapTweakHash`, `tweakPublicKey` (pubkey + parity + tweak), `tweakSecretKey` (privkey), and a tweaked-key `bip340.sign`→`verify` round-trip |

## Import

```zig
const taproot = @import("taproot");
const bip340 = @import("bip340");
```

## API surface

**The tagged hash** (usable standalone — e.g. for an independent
control-block/tweak verifier that doesn't need the full point arithmetic):

```zig
const t_hash = taproot.tapTweakHash(internal_pubkey_x, merkle_root); // merkle_root: ?[32]u8
```

`merkle_root = null` means "key-path-only, no script tree at all" — distinct
from a script tree whose root happens to be all-zero (which would append 32
zero bytes instead of nothing).

**Tweaked public key** (produced by `tweakPublicKey`):

```zig
pub const TweakedPublicKey = struct {
    x: [32]u8,
    parity: u1, // 0 = even y, 1 = odd y
};
```

**The two crypto cores** (see `root.zig`'s doc comments for the exact
BIP341 algorithm each implements):

```zig
const result = try taproot.tweakPublicKey(internal_xonly, merkle_root); // -> TweakResult{ .output, .tweak }
var q_bytes: [32]u8 = undefined;
try taproot.tweakSecretKey(&internal_sk, merkle_root, &q_bytes); // q_bytes = the tweaked signing scalar (big-endian)
```

A caller signs the output key's messages with `q_bytes` via
`bip340.sign`/`bip340.verify` against `result.output.asXOnly()` — this
module owns the tweak only, not signing.

**Script trees** — build an output that commits to scripts and get the
control block for each leaf:

```zig
const leaves = [_]taproot.DepthLeaf{ // depth-first (BIP371 PSBT_OUT_TAP_TREE order)
    .{ .depth = 1, .script = script_a },
    .{ .depth = 2, .script = script_b },
    .{ .depth = 2, .script = script_c },
};
var info = try taproot.buildFromLeaves(allocator, internal_xonly, &leaves);
defer info.deinit(allocator); // leaf scripts are borrowed, not copied
// info.merkle_root (?[32]u8), info.output.x / .parity, info.leaves[i].leaf_hash
var buf: [33 + 32 * 128]u8 = undefined;
const control_block = info.controlBlock(1, &buf); // (0xc0 | parity) ‖ internal_x ‖ path
```

An explicit shape works too: `taproot.buildFromTree(allocator, internal, &node)`
with `Node = union(enum) { leaf: Leaf, branch: [2]*const Node }`. Malformed
depth lists, leaf versions that are odd or `0x50`, and trees deeper than 128
return typed errors (`InvalidTreeShape`, `InvalidLeafVersion`,
`TreeTooDeep`). Verification of a spend is `bitcoinscript.tapscript`'s job.

When no layout is given, `taproot.buildFromWeights(allocator, internal, &[_]taproot.WeightedLeaf{ .{ .weight = 3, .script = a }, … })`
places the leaves by a Huffman layout (the two lowest weights joined first, as rust-bitcoin's
`TaprootBuilder::with_huffman_tree`); `taproot.huffmanLeaves` returns just the depth list. An empty list is
`EmptyTree`.

## Verify

```
scripts/modtest taproot
zig build test-taproot -Doptimize=ReleaseFast # ReleaseFast
```

The vector tests, the fuzz driver (`TAPROOT_FUZZ`) and the dead-stack probe are described in `SPEC.md` § Verification.

## Not provided

Script-path spending and sighash, control-block verification (that is `bitcoinscript`'s), BIP371 `PSBT_OUT_TAP_TREE`
byte encoding, address encoding and a NUMS internal-key helper; see `SPEC.md` *What is deliberately not done* and
*Backlog / deferred*.
