# `dataframe` — changelog

Newest first. See the root [`CHANGELOG.md`](../../CHANGELOG.md) for which
release tag each entry shipped in, and `CONVENTIONS.md` §8 for the policy.

## Unreleased

- **2026-11-10** — **ADDED** (parity, survey row 97): `jsonDecode(a, f, JsonDecodeSpec)`, polars `str.json_decode()`: every cell of a text column parsed as one JSON value, and the column of what they hold — the column `readNdjson` builds for one key holding those values (objects a `struct` with every key any of them has, arrays a `list`, scalars typed, a mix of kinds text), inferred over every row (polars' `infer_schema_length=None`); `type` as polars `dtype=` (a width narrow, out of range `error.BadValue`), `out` to keep the source, the reader's limits and `duplicate_keys`. A cell that is not exactly one JSON value is `error.BadJson`. Built over `jsonread`'s two passes (no second JSON parser). A verb, not an `Expr` arm: `Expr` types a column from its cells one by one, while the decoded schema needs every row.
- **2026-11-10** — **FIX** (W11, found by the fuzz driver, seed 81105): `concat` took its typed path for a piece declared with a width but storing Int64 cells, while the cell path stacked that column in its supertype, so a Float64 column came back holding ints on one path and floats on the other; a piece declared with a width now always goes by its cells. Fuzz after W11: 1,500,000 runs clean in 168 s (DATAFRAME_FUZZ, ReleaseSafe, one job).
- **2026-11-10** — **FIX** (W11, found by the fuzz driver, seed 6715): `concat` of hand-built pieces declared with a width over Int64 storage passed the raw cells on through the typed path (an Int8 column holding 35562772707820705) while the cell path nulled them; the typed path now conforms too, and `frame.conform` gives `.nulls` (no storage) when no cell is left, as every builder does.
- **2026-11-10** — **FIX** (no-panic sweep of the W11 width paths, `src/sweep_w11_test.zig`, plus the independent review's findings): a Float32 column holding an f64 past f32's range (reachable through `replace`, `replaceStrict` and the `topN` tail) panicked `format`, `writeCsv` and `writeJson` on the `+inf` the cast makes (now `inf` / `-inf`, JSON `null`), and those three verbs now `conform` their result to the declared width; `dtype.exactI128` refuses a whole float or decimal past ±2^64 (no width type holds one), which closes the `i128` overflows of `neg`, `abs`, `//`, `%` and `diff` over an integer-declared column holding such a cell; `unpivot` and a `join` coalescing a width key with a text key keep the text cells instead of nulling them; `aggregate` with `fx` over an integer width keeps the converted float of `min`/`max`/`first`/`last`/`mode`; `arith`/`arithScalar` `/` on Float32 is Float32 as `Expr`'s; `wideToLong` holds a UInt64 above Int64's top in a Float64 stub as a float; `sum_exact`, `horizontal` (`all`/`any`/`sum`/`min`/`max`), `eq_missing` and the list `sum` read a UInt64 above Int64's top; `mutate` of `min`/`max` over Int64 and UInt64 columns declares UInt64 (or Float64 beside a negative cell) rather than an Int64 column holding a `.uint` cell; `scatter` of `0.1` into a Float32 column rounds it as `cast` does.
- **2026-11-10** — **FIX** (W11, found by the fuzz harness once it checked every verb): `map` with a width `out_type` stored its float results under the width (storage and declared type disagreed); `appended` now conforms the new column, so a width holds the whole results that fit it and null for the rest. The fuzz harness checks `widthsConform` on every verb's result.
- **2026-11-10** — **CHANGED** (W11, one rule for every integer type): `aggregate` (and `groupByDynamic`) `sum` and `prod` of an Int64 column that stores ints alone are Int64, exact in an `i128`, null on overflow, as polars and pandas answer (they were Float64, added in f64, so 2^53 + 1 was lost; the old oracle listed it as a known difference, now gone). A declared Int64 holding floats keeps the Float64 sum; `sum_exact` is unchanged.
- **2026-11-10** — **ADDED** (dataframe S2 wave W11, the rest of the computing half): `concatByName` of pieces of different numeric widths meets in the supertype (`i8` with `u8` is Int16, `i64` with `u64` Float64; Int64 with Float64 still takes the first frame's type) and stores the declared width; `fillNull` (`zero`, `one`, `mean`), `horizontal` (`min`/`max` of one width, Float32), `clip` (a bound a width cannot hold turns the column float), `describe`, `quantiles`, `corr`/`cov`, `rle`, `extendConstant` and `binIntervals`/`binQuantiles`/`binRanks` take the width types (the bin verbs read a width column as Int64/Float64 and give the column back unchanged; the interval ends are Int64/Float64, polars keeps the column's dtype). New tests: `s2w11a_test.zig` and the replay of the polars vectors for supertypes, overflow, weak literals, unary, aggregates, group aggregates, combining and concat (`s2w11a_oracle_test.zig`, every difference a `known` entry with its reason).
- **2026-11-10** — **ADDED** (dataframe S2 wave W11, width-aware aggregates and window operations): `aggregate` and `window` over a width column follow polars' result types: `sum` of Int8/Int16/UInt8/UInt16 is Int64 (exact, in an i128) and of Int32/UInt32/UInt64/Float32 keeps the type, `prod` of an integer is Int64 (UInt64 keeps), a Float32 `sum`/`mean`/`median`/`std`/`var`/`quantile` is Float32 (computed in f64, rounded once: may differ from polars by an f32 ulp), `min`/`max`/`first`/`last`/`mode` keep the width, and an integer sum or product outside its type is null (polars wraps). `window`: `cum_sum`/`cum_prod` as the aggregates (an overflow nulls that row and the rest), `cum_min`/`cum_max` keep the width, `diff` keeps a signed width and makes an unsigned one the next wider signed type, Float32 through `diff`, `pct_change`, `rolling`, `expanding`, `ewm`, `interpolate`; `shift` casts its fill to the width (a fraction promotes). `aggregate`'s Int64 sum stays Float64 and `n_unique`/counts stay Int64 (unchanged).
- **2026-11-10** — **ADDED** (dataframe S2 wave W11, width-aware arithmetic): `mutate` computes with the width types. A binary arithmetic node is the polars supertype of its operands (`i8 + i8` Int8, `i8 + u8` Int16, `f32 * 2` Float32, `i64 + u64` Float64, `i64 + 2^63` Float64), an integer literal is weak (the column's type when it fits, `i8 + 1000` Int16, `u8 + 256` UInt16, `u8 + -1` Int16), `/` is Float64 (Float32 for `f32 / f32` and `f32 / i8`), integers compute exactly and an overflow is null (both engines wrap; `// 0` and `% 0` null as polars), `-x` of an unsigned column is `error.BadExpr`, `abs`/`neg`/`sign`/`pow` keep the width and the bit counts use its width, a Float32 node rounds operands and result to f32; `if_else` and `coalesce` meet in the supertype of their branches. The output column's type is the static type, not the cells' (`mutate` of a width expression is that width, empty and all-null results included); the compiler's type walk is capped at 4096 nodes per call. Int64 and Float64 expressions are unchanged.
- **2026-11-10** — **CHANGED / NO NEW API** (dataframe S2 wave W11, I/O edges and keys): `readCsv` with `thousands` or a `decimal` other than `.` reads a width column's numbers as it reads an Int64 or Float64 (they bypassed the normalisation); `CsvChunkReader` and `NdjsonChunkReader` take the widths in `types` like `readCsv`/`readNdjson` (a value out of range is `error.BadValue`, or null under `ignore_errors`); `format(show_dtypes)`, `glimpse` and `info` name a width by polars' short name (`i8` .. `u64`, `f32`); sort, distinct and the group keys read the narrow integer and Float32 arrays through the same fast key path as Int64 and Float64. Replays of the polars join, unique, sort, group_by and repr answers (`src/s2w11b_oracle_test.zig`) and a sweep of every verb of the files of part B on a frame with all eight widths (`src/s2w11b_test.zig`) are added.
- **2026-11-10** — **NO CONSUMER-VISIBLE CHANGE:** the fuzz harness (`src/fuzz.zig`) generates the eight fixed-width numeric types (minimum, maximum, 0, UInt64 above 2^63, Float32 subnormal / infinity / NaN) in frames and in `readJson` (`types`), and checks `frame.widthsConform` on the result of every verb of part B and on every reader's frame, CSV chunks included.
- **2026-11-10** — **CHANGED** (dataframe S2 wave W11, widths survive the verbs): a column declared with a width type (`int8`..`uint64`, `float32`) keeps its type and its own array through every verb that moves, reorders, reshapes or combines cells: `fillna`, `join` (a right-only key that the left width does not hold widens the key column to the supertype), `unpivot` (melted columns of different numeric types meet in their supertype), `pivot`, `unstack`, `wideToLong`, `transpose`, `combineFirst`, `update`, `scatter` (a value the width does not hold is `error.BadArgument`), `explode`, `flattenList`, `unnest`, `groupByDynamic`, `upsample`, the callback verbs and `repeatValue`; `arith`/`arithScalar` follow the supertype and polars' weak literal, `interpolate` keeps a Float32 column Float32; `Selector.numeric` and the `info`/dtype-line names know the widths. Int64 and Float64 columns behave as before.
- **2026-11-10** — **ADDED / BREAKING for an exhaustive switch** (dataframe S2 wave W11, the core of real dtype widths): `ColumnType` gains `int8`, `int16`, `int32`, `uint8`, `uint16`, `uint32`, `uint64` and `float32` (`int` stays Int64, `float` Float64); a column declared with one holds its own array (`ColumnData.int8` … `.float32`, made by `frame.conform` in `FrameBuilder.toOwned`, `cast`, `mutate` and the readers) and its cells read as `Value.int` / `Value.float`, widened exactly. `Value` gains `uint: u64` for a UInt64 cell above `maxInt(i64)`; it orders, compares, keys (one key with an equal float or decimal), sorts, joins and converts by its exact value. `cast` to a width range-checks (out of range: null, `CastFailed` with `.fail`) and `CastSpec.on_error` gains `.wrap` (polars `wrap_numerical`: an integer wraps, a float saturates, NaN 0). `readCsv`/`readJson` `types` accept the widths (a value out of range is `error.BadValue`, as polars' `read_csv`); the writers print a Float32 cell as its shortest f32 digits (`0.1`) and a UInt64 above 2^63 as its digits. New `dtype.zig` (predicates, ranges, `supertype`). Replayed against polars 2.1 in `s2w11_oracle_test.zig` (`tools/oracle2j.py`, 5451 cells of cast/read/write; every difference has a written reason). Arithmetic, aggregates and literals on widths follow in the next W11 commits.

- **2026-11-10** — **FIX** (independent review of wave W10): `wideToLong` sliced a column name shorter than `stub + sep` past its end (a panic) when the caller's `suffix` held an alternation that matched it (`suffix = "x)|(?:."`); such a name is now no stub column. - **2026-11-10** — **ADDED** (dataframe S2 wave W10, the cheap parity gaps): `Expr.find_regex` (polars `str.find`, byte offset), `corrWith` (pandas `corrwith`), `Expr.json_encode` (polars `struct.json_encode`, through `jsonio.writeValue`), `unstack` (polars), `wideToLong` (pandas `wide_to_long`), `binIntervals`/`binQuantiles`/`binRanks` (polars `bin_*`, with caps `max_bins`), each with oracle vectors (`tools/oracle2i.py`, 231 cases). **CHANGED:** `offset_by` on a zoned timestamp column moves the calendar units (`mo`, `q`, `y`, `w`, `d`) on the wall clock and adds the sub-day part as elapsed time (polars; it used to add elapsed time for everything); `Duration` gained a `days` field. - **2026-11-10** — **FIX** (found by the S2 fuzz arms, seed 493021): `split_fields` made its `n + 1` field names once per compile visit while the `max_nodes` budget counted the visit as one node, so a shared tower of `binary` nodes over a `split_fields` of 4096 fields was refused as `ExprTooLarge` only after 65536 visits (8 s, 2 GB). The names a `split_fields` makes now count against `max_nodes`; one at 4096 fields, or ten in one expression, are still accepted.
- **2026-11-10** — **FIX** (found by the S2 fuzz arms, seed 168996): `CsvChunkReader` counted a re-encoded record (one with an open quote, rewritten with every field quoted) at its re-encoded size against `max_bytes`, so a 166-byte input the whole read accepts under `max_bytes` 172 was `InputTooLarge` chunked; each queued record is now counted at the input's own size. The dataframe fuzz harness also generates every `Expr` arm, `Unary` op and `WindowOp` arm (shared and deep sub-expressions included).
- **2026-11-10** — **FIX** (triage of the S2 LOW backlog): `readJson` `.table` read a non-object element of `schema.fields` as the closing `]` and failed with `BadJson` (now skipped); `describeWith` labelled a `-0.0` percentile `-0%` (now `0%`) and, with two columns of one name, described the first twice; a zoned timestamp written to CSV/HTML lost the seconds of an offset (`-00:44:30`, as Python's `isoformat`), and the RFC 3339 writers printed an offset of -1..-59 s as `-00:00` (now `+00:00`); the chunked CSV reader's re-quoting no longer swallows `OutOfMemory`; `groupByDynamic` says `TooLarge` where it dropped a row's windows; `businessDayCount` finds the first holiday by search instead of a scan per row. - **2026-11-10** — **CHANGED** (S2 close, Unicode leftovers): `strip`, `lstrip`, `rstrip` and `strip_chars` with null `chars` strip Unicode whitespace from a valid UTF-8 cell (`unitext.isSpaceCp`, Python `str.strip()` as pandas: U+00A0, U+2003, U+3000, U+0085, U+2028 and U+001C..U+001F go, U+200B does not; polars differs only on U+001C..U+001F); an ill-formed cell and an explicit `chars` are unchanged. The `alpha` / `alphanumeric` selectors use the Alphabetic property (`unitext.isAlphabeticCp`, as polars `cs.alpha()`), so names with combining vowel signs (Devanagari, Thai) are alpha; `digit` stays `Nd`. `tools/oracle2f.py` gained the strip cases and such names; vectors re-taken (pandas 3.1, polars 2.1).

- **2026-11-10** — **FIX** (no-panic sweep of the S2 code, B-1): `NdjsonChunkReader` kept every blank line of the stream in its chunk text, and its `max_bytes` check counted a bare `\n` as zero bytes, so a stream of blank lines grew the chunk without bound. Blank lines (empty after trimming space, tab and CR) are now dropped before they are buffered; `readNdjson` skipped them anyway, so rows and chunk sizes are unchanged.
- **2026-11-10** — **FIX** (no-panic sweep of the S2 code, A-1..A-5, A-7, A-10): (A-1, HIGH) the schema walk behind nested list types (`list.first`/`get`/`last`/`min`/`max`/`item`) took two recursive walks per level, so a chain of 60 such nodes hung `mutate`; it is one walk now. (A-2, HIGH) `list_eval`, `list_filter` and `struct_fields` compiled their bodies with a node budget of their own, so a DAG sharing operand and body was walked 2^depth times; the whole expression now shares one `max_nodes` budget (`error.ExprTooLarge`). (A-3) `corr`/`cov` cap the result matrix at `max_corr_cells` = 2^26 cells (8192 columns) — a frame of 0 or 1 rows passed the work cap with any column count; `error.TooLarge`. (A-4) `cumFoldColumns`/`cumSumHorizontal` with a column named many times are bounded like the other verbs that multiply a frame. (A-5, A-7) `struct.map_fields`' duplicate-name check and `struct_fields`' compile were quadratic in the field count; now hashed. (A-10) `repeatValue` weighs a nested value at every level (a list holding a 1 MiB text counted as 17 bytes), so `max_repeat_bytes` holds.
- **2026-11-09** — **FIX** (found by an independent review of the remaining S2 files): `list_sample` with `fraction = inf` over an empty list computed `0 * inf` = NaN and cast it (a panic); an infinite fraction is `BadExpr` when compiled, and the cell path refuses a NaN product; a draw past the length without replacement answers null before allocating `n` cells. `repeatValue` weighs the copies (`max_repeat_bytes`, 2^30) instead of only the rows (16 MiB text × 4 M rows allocated 64 TiB), and a declared `ty` other than the value's kind converts the cells by `cast` (`error.BadArgument` when it cannot) — the column's storage and declared type used to disagree. `hist` with finite ends whose distance overflows (-1e308 .. 1e308) is `BadArgument`, not NaN edges. `clone` keeps a declared nested schema (`inner`: element type and zone), deep-copied. `renameReplace` with a pattern frees its compiled regex (it leaked on every call under a non-arena allocator). Ten LOW notes are in § Backlog.
- **2026-11-09** — **FIX** (found by an independent review of the S2 JSON code): `readJson` `.table` stored the Table Schema `tz` of a column as a slice of the caller's input (use after free once the caller freed it); the frame now owns a copy. `readNdjson` (and so `NdjsonChunkReader`) ignored `epoch_dates`, `epoch_durations` and `date_unit`; they apply as in `readJson`. A name repeated in one epoch list converted twice (1000× too large); it is `error.BadValue`, as a name in both lists already was. `writeJsonOpts` with `indent` counted only the compact document against `max_indent_bytes`; the indented output is counted as it is written (an `indent` of 255 could turn 1 MB into ~380 MB), and the Allocating writer's failure is `OutOfMemory`. The `.split` duplicate-name check is linear (was quadratic in up to 65536 names). **API change:** `writeJson`/`writeJsonOpts` `.table` of a frame with a column named `index` is `error.BadOptions` (`JsonDocError`), not a document whose duplicate `index` key the reader refuses or drops; pandas refuses it too. Four LOW notes are in § Backlog.
- **2026-11-09** — **FIX:** a `join` that coalesces the key (`coalesce_keys`, or `sort`) of a `full`/`right` join with right-only rows rebuilt a categorical key as plain text under a declared `.categorical`: the dictionary and `ordered` were dropped and `sort` ordered the keys by text, not by category (an Enum `low < high` came out `high, low`). Both sides stored as the same categorical now keep codes, dictionary and order; different dictionaries are encoded again lexically, as `concat` does. **Behaviour change:** `sort` with `keep_right_keys` (polars `coalesce=False`) no longer fills the left key of a right-only row from the right; it stays null and sorts last. Found by an independent review; seven LOW notes are in § Backlog.
- **2026-11-09** — **FIX:** `dt_combine` (`dtfn.timeOfDayUs`) took a signed time of day: `parseInt` accepts a sign, so `"-1:30"` combined to 23:30 the day before, `"10:-5"` to 09:55 and `"12:30:00.-5"` to half a second early. Every position of `HH:MM[:SS[.ffffff]]` except the separators must now be a digit, else null. Also `dtfn.bucket` refuses a non-positive step itself (null) instead of relying on every caller, so a zero `Duration` can never divide by zero. Found by an independent review; four LOW notes are in § Backlog.
- **2026-11-09** — **FIX:** `readCsv` with a layout-parsed date (`parse_dates` + `date_format`, or a `types` override `.date`/`.timestamp` with a `date_format`) gave every such column of a row the value of the last one (silently wrong data, or a dangling text when the lengths differed): the cells of a row were parsed into one shared scratch arena that each parse reset, and the row was appended only afterwards. The arena is now reset once per row, so each cell stays valid until `appendRow` copies it (type inference in pass 1 the same way); `CsvChunkReader` reads through `readCsv` and is fixed with it. Found by an independent review. Also the `BadOptions` doc now says what the code checks (`thousands` = `decimal` or `decimal` = 0; a `thousands` byte equal to the delimiter works for quoted cells). Tests in `src/io_s2_test.zig` and `src/s2w9_test.zig`; the remaining LOW notes are in SPEC § Backlog.
- **2026-11-09** — **FIX:** four `more.zig` corners, found by an independent review. `describeWith` with many `percentiles` (up to 65536) deduped the row names and looked each cell up by comparing against every row (~n² string compares, minutes) and had no output cap; both are linear now (a hash of the names) and rows × columns above `max_aggregate_cells` is `error.TooLarge`. `cut` with `bins` and `interval_labels` built the texts of every bin, used or not (a 3-row frame with 2^20 bins cost seconds and 100+ MB): above `max(rows, 4096)` bins that combination is `error.TooLarge` (**stricter**; plain `bins` keeps 2^20). `quantiles` bounds probabilities × (rows + 1) × (columns + 1) by the new `max_quantile_work` (2^30 row visits; each probability is a pass over the rows), not by the output-cell cap, so a few quantiles of a multi-million-row column still pass. `binEdges` (and `cut` with `bins`) answers `error.BadEdges` for finite extremes whose range overflows (edges were NaN). Tests in `src/s2w2_test.zig`.
- **2026-11-09** — **FIX:** two `groupByDynamic` defects (`frameops.zig`), found by an independent review. On a zoned index an aggregate of the index (min/max/first/last over the timestamp column) came back as wall-clock microseconds, typed timestamp and zone-less, i.e. shifted by the UTC offset; every output column holding an index-derived instant (the index, the boundaries, each aggregate whose source is the index and whose type is a timestamp) is now converted back and carries the zone. And the (row, window) replica copied every column of the frame once per pair (100k rows × 100 columns × ~160 windows ≈ 12.8 GB before any error): it now copies only the index, the `by` keys and the aggregate sources, and pairs × copied columns above `max_join_cells` is `error.TooLarge`. Tests in `src/s2w7_test.zig` and `src/s2w5_test.zig`.
- **2026-11-09** — **NO CONSUMER-VISIBLE CHANGE (SPEC only):** an independent review of the S2 `exprfn.zig` changes (Unicode case, normalize, unaccent, classes, `escape_regex`, `erfc`) found no panic, no unbounded work and no MED defect; four LOW notes are in § Backlog.
- **2026-11-09** — **FIX:** two `strfn.zig` defects, found by an independent review. `wrap` with one long word counted its characters and validated its UTF-8 over the whole remaining chunk for every output line, so a 1 MiB word at width 1 cost ~n²/width byte operations (minutes; a hang at the 16 MiB cell cap); the count is now bounded by the width and a chunk's validity is decided once, so the work is linear. **Edge on invalid UTF-8:** a chunk that is not valid UTF-8 is now handled as bytes for all its lines, where a suffix of it that happened to be valid after an earlier line was cut used to count characters again. Valid text is byte-identical. `splitColumns` built every piece of a cell before checking `max_str_columns` (16 MiB of `,` made ~16 M values in the arena); it is now `error.TooLarge` as soon as the cell has more pieces than the cap (literal, regex and whitespace splitters). Tests in `src/s2w4_test.zig`.
- **2026-11-09** — **FIX:** five `expr.zig` defects, found by an independent review. `Expr.is_business_day` and `business_day_count` read the UTC day of a zoned timestamp while the `dt` part `is_business_day` read the local one (Monday 07:00 in Tokyo was a Sunday); both now use the operand's local date. `is_between` and `fold` with a comparison operator bypassed the ordered-categorical comparison (lexical text order); they now share `go(.binary)`'s path. `list_eval`/`list_filter` dropped the declared element's `time_zone`, so `dt` parts of `.element` read UTC. The static helpers `zoneOf`/`temporalType` (and `elementColumn`) now run only after `go` has bounded the operand (`max_depth`/`max_nodes`): a shared-child `if_else` DAG of depth ~45 cost ~2^45 helper calls, a very deep chain overflowed the stack; both are `error.ExprTooLarge` at once. **API change:** (stricter) `CastSpec.ordered = true` with `to` other than `.categorical` is `error.BadExpr`, as `categories` there already was. Tests in `src/s2w6_test.zig` and `src/s2w7_test.zig`.
- **2026-11-09** — **FIX:** three `window.zig` corners, found by an independent review. `rolling_time`/`rolling_rank`/`rolling_corr` with `closed = left/neither` walked back over every earlier row tied at the row's time, work `max_window_work` did not count (n rows at one time cost ~n²/2 steps); the run of tied times is now tracked, so the window end is O(1), and a null between ties no longer leaves an earlier tie inside the window. `rolling(win_type=)` generated its weights (up to 4.2 M points) once per partition outside every work counter; they are now generated once per call. A `shift` with an int-to-float fill promoted the column's declared type but kept `.int` cells on the `explode`/`join` mappings.
- **2026-11-09** — **Fixed (before release):** three corners of the chunked readers, found by an independent review. `CsvChunkReader` with `ignore_errors` probed each cell with the caller's `max_bytes`/`max_record_bytes`, so a cell that passed the stream caps could fail the read with `RecordTooLarge` instead of becoming null (the probe text is longer than the cell); `NdjsonChunkReader` counted the `\n` it adds after each line against `max_bytes`, so a last line without a newline at exactly `max_bytes` was refused where `readNdjson` takes it; and `CsvChunkReader` queued a record's buffer before its `ends`/`lines` slots, so an out-of-memory in between left them out of step and a later `drop`/`locateBadLine` could index past `lines` (now reserved first). Tests in `src/s2w9_test.zig` (the OOM ordering has none).
