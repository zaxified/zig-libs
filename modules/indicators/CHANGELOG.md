## Unreleased

- **2026-11-24** — Batch speed, bit for bit unchanged: `cksp`'s block-wise pass takes the better of two finite values with a plain compare-select (one `maxsd`/`minsd`, not `@max`'s NaN fix-up) and runs the steady bars in four phases with a branch-free body each; 2.40x to 1.74x TA-Lib at 1e5 bars (shield, spread < 4 %).
- **2026-11-21** — Batch speed, bit for bit unchanged: `cksp` on finite, non-zero input runs one pass of four block-wise rolling extrema and the inline Wilder ATR (as TA-Lib's own CKSP) instead of five generic cores, 2.5x faster at 1e5 bars (5.9x to 2.1x TA-Lib); it takes `2 * (period + stop_period)` f64 of scratch from the allocator (the generic core, `2 * stop_period`, answers when that is not available or the input has a zero, a NaN or an overflow). Benchmark rows `pso` and `cksp` added.
- **2026-11-21** — **API addition:** `MavpStream(T)` (and `MavpIn`), the streaming MAVP: a bank of one moving average per period in `min_period..max_period` as in TA-Lib 0.8's `TA_MAVP_Update`, `update(.{ .close, .period })`, bit for bit the batch `mavp`, `peek`, `clone`. Its buffer holds the bank (one `MaCore` per period): `bufLen` is megabytes for a wide range. Every one of the 237 functions now has a streaming type.
- **2026-11-16** — Batch speed (third round, bit for bit unchanged): MINMAX (period <= 256) takes both extremes from one block
  scan (`window.hiLoBlocks`, `extBatch`'s comparisons) instead of two `extBatch` passes — 1.59x TA-Lib before, 0.77x now.
- **2026-11-16** — Batch speed (third round, bit for bit unchanged): FRAMA (f64, no NaN skipping) runs its four extremum
  automatons as `ExtCore.Run` over the slices (the older half window is the same automaton fed `half` bars later) and joins
  the whole window's extremes in one two-lane vector select — 2.0x TA-Lib before, 1.85x now; the rest is `exp` and `log` per bar
  (profiled: Zig's `exp` takes about 2.5x the cycles of glibc's per call).
- **2026-11-16** — Batch speed (third round, bit for bit unchanged): STOCHRSI (f64) runs as three passes over series instead of
  three cores per bar: the RSI, the stochastic of the RSI values (`stoch.kSeries`, the same automaton) and its average
  (`stoch.maStage`, one dispatch per call), the outputs swapped and blanked before the first %D — 2.0x TA-Lib before, 1.03x now.
- **2026-11-16** — Batch speed (third round, bit for bit unchanged): HMA (period >= 4) runs its three weighted averages as one
  TA-Lib shaped loop with the sums in locals, the value each average drops re-read from the input (from the ring slot about to
  be overwritten, for the outer one) instead of carried, and each re-anchor due at a bar number instead of three count-downs
  in memory (profiled: 2.4x the instructions of TA_HMA, spilled counters, no branch misses) — 2.4x TA-Lib before, 1.03x now.
- **2026-11-16** — Batch speed (third round, bit for bit unchanged, NaN inputs included): PERCENTILE and MEDIAN find their
  positions in the sorted window by counting with four-lane compares (`<=` and `<`, one pass for the new and the leaving value,
  the position shared by the answer and the shift) instead of binary searches whose probes mispredict, and shift with
  `@memmove`; once a NaN has entered a window the order is broken and the cores keep the searches for good, so their answers
  there are unchanged too — PERCENTILE 2.5x TA-Lib before, 1.19x now; MEDIAN 1.34x -> 0.64x.
- **2026-11-16** — Batch speed (third round, bit for bit unchanged): the variance window `bands.VarCore` gains `steadyStep` (the
  full-window step without the warm-up tests and the `?f64`, its running-peak update a vector select instead of the branch LLVM
  made of the ternary); VAR and STDDEV run it as a `steadyRun` loop, BBANDS from its first output on — VAR 2.1x TA-Lib before,
  0.94x now; STDDEV 1.4x -> 0.62x; BBANDS 2.3x -> 1.28x (1.41x at 1e3).
- **2026-11-16** — Batch speed (third round, bit for bit unchanged): ALMA (f64, period > 1) runs eight bars side by side as two
  four-lane accumulators, each lane one bar's dot product with the scalar loop's operations in its order (seed 0.0, separate
  multiply and add, weight order) — 2.5x TA-Lib before, 0.52x now.
- **2026-11-16** — Batch speed (third round, bit for bit unchanged): STOCH, STOCHF and KDJ (f64) compute the raw %K with the
  two extremum automatons run as `ExtCore.Run` over the slices (same rescans, same tie rule, no `?f64` per bar) and run each
  smoothing stage as one `MaCore` dispatch per call with the variant's monomorphic loop (`smooth.runCore`) instead of a
  per-bar union switch — STOCH 2.3x TA-Lib before, 1.11x now; STOCHF 1.8x -> 1.14x; KDJ 2.5x -> 1.05x.
- **2026-11-16** — Batch speed (P-gap work, third round; every output bit for bit unchanged, NaN inputs included): CRSI counts its
  percent rank over the ring buffer as one contiguous slice with eight-lane compares (an integer count, so in any order) instead of
  a `%`-indexed `src.at` per window value — 3.4x TA-Lib before, 0.42x now.
- **2026-11-16** — Batch speed (P-gap work, second round; every output on NaN-free data bit for bit unchanged):
  MIDPOINT, MIDPRICE, WILLR and ICHIMOKU (f64) run TA-Lib's block scan of the window extremes (`ta_MIDPOINT.c`,
  `ta_WILLR.c`, three `TA_MIDPRICE` calls; new `window.hiLoBlocks`, stack scratch up to period 256, the automaton
  above) — 3.5x / 2.2x / 3.1x TA-Lib before, 0.68-0.93x now; STC keeps its two stochastic windows with TA-Lib's
  online block scan (`ta_STC.c`'s rings with suffix arrays) instead of rescanning them through a `%`-indexed ring
  each bar, branchless — 6.4x to 1.9x; MFI takes the leaving money flow from a stack ring in the batch (period up
  to 256) and selects its flows without branches — 3.3x to 1.5x; HMA has a fused steady loop without `%` — 3.9x to
  2.4x. **Behaviour change where a NaN is in a window:** the batch MIDPOINT / MIDPRICE / WILLR / ICHIMOKU now answer
  as TA-Lib's batch does (block scan), which can differ from their streams there (as MAX / MIN / MINMAX already
  did); STC's stream and batch both follow TA-Lib's block scan, so a window holding a NaN or a 0.0 / -0.0 tie can
  answer differently from before. **`StcStream.bufLen` grows** from `2 * cycle` to `6 * cycle + 4` f64 (callers
  that size the buffer with `bufLen` are unaffected).
- **2026-11-15** — ALMA through `MaCore` (MA, MACDEXT, BBANDS, ... with `.alma`) uses a precomputed weight table for periods up to 64
  (inline in the core, no allocator; larger periods keep the per-bar recompute): 27-38x faster on a 1e5-bar series, output bit for bit
  unchanged. `Stream1`'s dead NaN-skip branch is removed (a ring core with a `nan` parameter is now a compile error). Delta mutation: 6
  mutants on the changed lines, 3 killed, 3 equivalent (cost only / unobservable); live oracle all agree.
- **2026-11-15** — NO CONSUMER-VISIBLE CHANGE (performance): windowed batch paths, outputs bitwise unchanged (live oracle: identical per-function statistics; new test: WILLR / CCI batch against the stepped core on data with +0.0 / -0.0 ties, NaN and inf). MOM / ROC family: a branch-free steady step (`vs.run`, whose `steadyStep` now also receives the history source). CCI (f64): the typical prices are parked in the output and every window is summed as two contiguous runs in TA-Lib's circular-buffer slot order, no index wrap and one division per bar (3.9x -> 1.4x TA-Lib); f32 keeps the generic step. MIDPOINT: the cached-index extrema run in registers (`window.ExtCore.Run`, 4.0x -> 3.8x). MOM 1.55x -> 0.98x, ROC 1.06x -> 0.88x.
- **2026-11-15** — NO CONSUMER-VISIBLE CHANGE (performance): batch paths without per-bar dispatch or warm-up branches, outputs bitwise unchanged (live oracle: identical per-function statistics; batch == stream tests and the frozen vectors pass). (a) `MaCore` is dispatched once per call, the loop runs over a by-value copy of the active variant: MA, APO / PPO, BBANDS, and MACDEXT when its three stages share an MA type. (b) Recurrence cores declare `steady()` plus a tight loop (`steadyRun`: EMA, DEMA / TEMA / T3, KAMA, ATR / NATR; MACD's three EMAs in `batch3`) or a branch-free `steadyStep` (`vs.run`: TRIX, TSI, APO / PPO over EMA) that the batch drivers switch to after the warm-up; NaN-skipping calls and the streaming types keep the generic step. TA-Lib ratios: APO 18.5x -> 1.23x, PPO 15.9x -> 1.47x, MA(EMA) 10.9x -> 1.00x, MACDEXT 3.88x -> 0.87x, EMA 1.87x -> 1.00x, MACD 3.5x -> 1.31x, T3 2.8x -> 1.00x, TEMA 3.76x -> 0.96x, KAMA 3.2x -> 1.12x, ATR 2.1x -> 1.01x, TRIX / TSI / DEMA -> 0.98-1.04x, BBANDS 3.8x -> 2.10x.
- **2026-11-15** — NO CONSUMER-VISIBLE CHANGE (performance): `xmath.atan` gets a Ziv fast path: a table-driven double-precision evaluation (65-node `atan(i/64)` double-double table, one reduction `t = (y - c) / (1 + y c)`, a degree-9 series, error below 2^-64, bound 2^-62) whose result is returned when the bound cannot straddle a rounding boundary, else the double-double path decides as before, so every answer is bitwise the previous one (new test: 60,000 sampled arguments plus the table nodes, their reciprocals and neighbours, against the double-double path, distance <= 2^-64). HT_DCPERIOD / HT_PHASOR 14.7x -> 1.45-1.48x TA-Lib, MAMA 23.0x -> 1.69x, HT_TRENDLINE 8.1x -> 1.30x, HT_SINE / HT_DCPHASE 3.5x -> 1.05x; live oracle unchanged (same per-function counts).
