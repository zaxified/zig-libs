### Conventions, and where the three libraries disagree

Pinned by tests against all three on seeded series (`tools/oracle.py`, tolerance 1e-11 relative:
the libraries agree with each other to 2e-15; a wrong divisor, rf conversion or threshold
shows at 1e-4 or more):

- **Annualisation** (label A). `periods_per_year` default 252. `cagrPeriods` counts rows
  (empyrical `annual_return`, quantstats `cagr(periods)`, equal). ffn `calc_cagr` instead uses
  calendar time between the first and last date of a PRICE series (measured -0.1614 against -0.1522
  on one oracle series) and is NOT what `cagrPeriods` computes. `riskMetrics` follows ffn's
  calendar idea through `date_col`.
- **Risk-free rate** (label R). `rf` is annual, compounded to a period, (1 + rf)^(1/ppy) - 1, then
  subtracted from each return (quantstats `rf` + `periods`). empyrical takes the per-period rate
  directly (same number once converted); ffn 1.3.0 `calc_sharpe` agrees to 1e-12 on the test
  series. Geometric excess ((1+r)/(1+rf_p) - 1, ffn's `to_excess_returns`) was not what 1.3.0's
  Sharpe used on these inputs and is not offered.
- **ddof** (label D). Sample standard deviation, ddof 1, as pandas and empyrical `nanstd(ddof=1)`.
  scipy `skew`/`kurtosis`, PerformanceAnalytics and `skewness`/`excessKurtosis` here are
  population (ddof 0); `riskMetrics.downside` divides by n (all three libraries).
- **Downside threshold** (label T). `sortinoRatio` measures the downside against rf_p (empyrical and
  quantstats; all three equal at rf 3 %). `riskMetrics.downside` is against 0 (documented since
  2026-10-04).
- **Compounding** (label C). `totalReturn` is Π(1+r) - 1 (empyrical, quantstats `comp`). quantstats'
  `recovery_factor` uses the SUM of returns, and so does `recoveryFactor` here (pinned), which
  is not total return / drawdown. `geometricMean` is per period, not annualised.
- **Sharpe, two flavours** (label S). `sharpeRatio` = mean excess / std * sqrt(ppy) (all three
  libraries). `riskMetrics.sharpe` = calendar-day CAGR / annualised std (the module's older
  convention, kept for result stability; no library computes it). Output names keep them apart
  (`sharpe_mean` in `periodStats`).
- **Non-finite input, empty series, zero variance** (label E). See the next section.

### Edge cases (defined, tested in `src/edge_test.zig` and `src/sweep_test.zig`)

- Empty series: every scalar is 0, every node row is 0, never NaN; `cumulativeReturns` has no rows.
- Fewer than two periods, or zero spread (a constant series, to rounding): the ratio is 0 (not
  inf, not a 1e16 Sharpe). Zero downside or zero drawdown: 0. `gainToPain` and `recoveryFactor`
  with a positive numerator and a zero denominator: +inf (as `omegaRatio`).
- All-negative returns: finite, signed.
- NaN or infinity in a return: every function of this section, plus `riskMetrics` and
  `tradeStats`, answers NaN for the whole result (previously `riskMetrics` mixed finite and NaN
  cells, because `@min` and `<` skip a NaN). A return below -1 is not a return: the compounding
  functions AND `riskMetrics` (whole row; it printed a drawdown of -150 % before) answer NaN.
  This reaches wgs, which feeds `twr_daily` into `risk_metrics`: bad flow data that makes a
  daily TWR drop below -1 now yields a NaN row instead of plausible numbers.
- Long series keep their accuracy: the compounded level is renormalised (`levelOf`), so 80 000
  periods of -1 % give the right CAGR instead of -1, and a level past the f64 range no longer
  turns the drawdown into NaN terms that `@min` skips. A constant series has a spread of exactly
  0 for any n and level (deviations are taken from the first element). A null cell is 0 as before. Bad parameters (ppy <= 0 or non-finite,
  rf <= -1) give NaN, never a panic.
- Very long series: two passes with lane-wise accumulators; a 2 000 000-period series is tested;
  a level that overflows to +inf gives +inf total return, no panic.

## Design & invariants
**One surface, plain slices (step R of `~/CML/20261105-dataframe-split/plan.md`, done 2026-11-08).** Every function lives in `slice.zig` (with `ratios.zig`, `calendar.zig`, `overfit.zig`, `factor.zig`, helpers in `core.zig`) and `root.zig` re-exports each public declaration by name; `finstats.slice` stays as an alias namespace for one release and is deprecated. There is no table type in the module: inputs are `[]const f64`, dates are ISO `YYYY-MM-DD` text, a result row is a named struct. The `Dataset` functions and their error set (`NoSuchColumn`) are gone, so a bad date is `error.BadDate` everywhere (it used to read as 1970-01-01 in the `Dataset` functions) and a NaN flow is `XirrNoRoot` in `xirr` (it used to be dropped). The rest of this section keeps the conventions the old `Dataset` text stated, which did not change; `slice.zig`'s head comment states the error rules.

Portfolio/financial statistics over plain slices: dated-flow IRR (`xirr`, plus a Newton-with-
bisection-fallback sibling `xirrPrecise`), daily time-weighted return
(`twrDaily`, Modified-Dietz), risk metrics (vol/VaR/CVaR/Sharpe/Sortino/Calmar/Ulcer/max-drawdown via
`riskMetrics`, historical/empirical), parametric VaR/CVaR at an arbitrary confidence (Gaussian via
`gaussianVaR`/`gaussianCVaR`, skew/kurtosis-adjusted Cornish-Fisher via `cornishFisherVaR`/
`cornishFisherCVaR`, bundled per-series as `parametricRisk`), beta/alpha/R² (`betaAlpha`), tracking
error + information ratio (`trackingRisk`), the Omega ratio (`omegaRatio`), a generic rolling-window
reducer (`rollingApply`, plus `rollingMean`/`rollingVolatility`/`rollingSharpe` wrappers), a seeded
Monte-Carlo net-worth projection (`monteCarlo`), a pairwise-Pearson correlation matrix
(`correlationMatrix`), a drawdown-episode state machine (`drawdownEpisodes`), and Brinson-Fachler
performance attribution (`brinsonAttribution`). Every function is a pure function of its
slices and a caller-owned allocator (normally an arena): scalar reducers return the number,
series producers an owned slice, table producers a slice of row structs — no hidden state, no I/O. Numeric conventions are exact and
deliberate (decisions, not bugs): `xirr` is 200-iteration bisection over `[-0.99, 10]`, ACT/365.25
day-count, tolerance `1e-2` (kept exactly as-is; `xirrPrecise` is an additive Newton-first sibling
that falls back to the same bracket/bisection on non-convergence). Both first check that NPV
changes sign across the bracket and return `error.XirrNoRoot` when it does not — a bracket bound is
indistinguishable from a real answer at the call site, and used to be returned as one. Both also
take a REQUIRED `opening` argument selecting whether the first row's value is seeded as a
starting position, which is what a series sliced to a date-range window needs. It carries no
default deliberately: the sign-change check cannot catch a forgotten seed in general (a window
whose first row happens to carry a flow does bracket a root, and converges on the IRR of a
different question), so a compile error is the detector (a positional argument, so it cannot be
left out by accident). Both also narrow the RATE
below `rate_tol` (default 1e-9) before returning, because the `1e-2`/`tol` thresholds are on NPV
and therefore mean different things at different cashflow magnitudes — on a series denominated in
units of ~0.01 the old test was met at the first midpoint and `xirr` returned 4.505 for a series
returning 10 %; `rate_tol = null` restores that behaviour bit-for-bit for a caller pinned to old
numbers. `riskMetrics`' `var95`/`cvar95`
are historical (empirical), not a parametric fit — the parametric fit lives in `parametricRisk`
instead, at a caller-chosen `confidence` (95%/99%/…), where `cornishFisherCVaR` integrates the
CF-adjusted quantile function (fixed-step trapezoidal quadrature) rather than a naive `φ(z_cf)/α`
plug-in, because that shortcut can report CVaR below VaR for negative-skew/fat-tailed inputs (see
its doc comment); `monteCarlo`
uses a fixed-seed deterministic PRNG (`std.Random.DefaultPrng`, seed `0x9E3779B97F4A7C15`) via
Box-Muller so percentile outputs are reproducible/regression-testable; `correlationMatrix` gates
pairs on `min_overlap` (default 30); `brinsonAttribution` is the Brinson-Fachler variant
(benchmark-relative allocation term `rb_i − Rb`), whose three effects sum exactly to the portfolio's
active return `Rp − Rb`, an algebraic identity (assumes weights each sum to 1) pinned by test. f64
throughout — deliberately no `decimal` dependency: risk
statistics are inherently floating-point, `decimal` is for exact ledger arithmetic, not variance/
quantile math. Platform: any (pure logic, no OS calls). Role: util. Concurrency: reentrant (no
shared state). Depends on `datefmt` (civil calendar) only. Original work of the zig-libs authors, modeled after the
Python `empyrical`/`ffn` metric set and a QuantLib subset (mirrored, not invented — behavior/
metric-set only, no code consulted or copied); the numeric behavior is exact, pinned by the tests.
See README "Provenance".

## Threat model / out of scope
Not security-sensitive; the contract is numerical fidelity to the documented conventions above, not
defense against hostile input — series of different lengths and a date that is not a real ISO
date surface as typed `error.LengthMismatch` / `error.BadDate`, never a panic; allocation failure surfaces as `error.OutOfMemory`. Out of
scope / deferred (a faithful v1 lift, not a complete risk-analytics suite): arbitrary
annualization-frequency presets/bounds checking (`periods_per_year` is a free 252-defaulted knob,
same as before); confidence intervals/standard errors on the statistics. (Parametric VaR/CVaR,
tracking error/information ratio, Omega ratio, rolling-window variants, Brinson attribution, an
arbitrary VaR confidence level, and an xirr Newton-with-bisection-fallback were all backlog items
here — now implemented, see Design & invariants above.)
